# MotionBricks SOMA golden fixtures

These files pin the C++ SOMA math core against NVIDIA's official MotionBricks
v0.2.0 implementation.

- `soma_n1.json` is copied from
  `motionbricks/assets/onnx/soma/soma_n1.json` in
  <https://github.com/NVlabs/motionbricks> (Apache-2.0). It is the model
  manifest, not model weights.
- `soma_golden.json` is generated by `generate_soma_golden.py` running the
  official Warp kernels on CPU. It contains a synthetic 30-joint SOMA-like
  skeleton, synthetic context/target poses, the encoded input tensors, a
  synthetic prediction, and the official decode / endpoint-correction /
  sampling results.
- `soma_inference_golden.json` is generated by
  `generate_soma_inference_golden.py` running `mmm_v6_soma_fp32.onnx` with
  ONNX Runtime 1.22.0 CPUExecutionProvider. It pins the C++ ONNX session
  wrapper's `pred_global_motions` and token count against the official Python
  runtime. It contains model output, but no model weights.
- `soma_calibration_motion.json` stores a synthetic SOMA bind-pose prediction
  for reference-space diagnostics without model weights or motion data.
  With the T-to-A source calibration its output need not equal the UEFN bind pose.

- `soma_locomotion_targets.json` contains four 30 Hz poses for each of the
  official SOMA Idle/Walk/Jog/Run targets. Unlike the synthetic golden vectors,
  these are sampled motion data from MotionBricks' `locomotion_bs1_linear`
  Smart Primitive and its referenced BVH clips. No model weights are included.
  Regenerate with `tool/animation/export_motionbricks_locomotion.py`; the
  upstream BVH files must be downloaded through Git LFS first. The exporter
  needs Warp, NumPy and SciPy and preserves source joint names for reordering.
  These sampled motion values are covered by the separate NVIDIA Sample Data
  Evaluation License in `MOTION_SAMPLE_LICENSE.txt`, for internal evaluation
  and testing of NVIDIA technologies.

The ONNX integration test is skipped unless both of these are present:

```powershell
$env:VULKANLEARN_ONNXRUNTIME_DLL = "D:\path\to\onnxruntime.dll"
$env:VULKANLEARN_MOTIONBRICKS_SOMA_ONNX = "D:\path\to\mmm_v6_soma_fp32.onnx"
```

`VULKANLEARN_ONNXRUNTIME_DLL` is optional when `onnxruntime.dll` is already on
the Windows loader search path. The DLL must expose C API version 22
(ONNX Runtime 1.22).

`motionBricksLiveTests.cpp` uses the same model for the background live
generation path. The `ExecutionProviderSelection` test also probes optional
DirectML/CUDA backends; `auto` only attempts providers that are actually
installed and falls back to CPU.

Regenerate after changing the C++ core or updating the upstream reference:

```powershell
uv venv .venv-motionbricks --python 3.12
uv pip install --python .venv-motionbricks\Scripts\python.exe "warp-lang>=1.17" "numpy==2.4.3"
.\.venv-motionbricks\Scripts\python.exe tool\animation-tests\fixtures\motionbricks\generate_soma_golden.py `
  --motionbricks-root D:\path\to\motionbricks `
  --output tool\animation-tests\fixtures\motionbricks\soma_golden.json

.\.venv-motionbricks\Scripts\python.exe tool\animation-tests\fixtures\motionbricks\generate_soma_inference_golden.py `
  --model D:\path\to\mmm_v6_soma_fp32.onnx
```

`--motionbricks-root` is the checkout containing the `motionbricks` package
(the repository root, not the package directory). The script sets Warp's device
to CPU so the fixture is reproducible without CUDA.
