# Rationale：决策、证据与历史

> 状态：**非契约**。这一层解释**为什么**，不描述**现在是什么**。

## 这一层能信到什么程度

这里的内容**不能当事实用**。它记录意图、取舍、被否决的方案、以及已经退役实现的历史。
其中的技术描述可能随实现演进而过时，而**没有人会回去更新它**——这是它被隔离在这里的原因。

需要当前事实时读 `documents/contracts/`；需要"改这个路径该读什么"时读 `documents/routing.md`。

## 目录内容

| 路径 | 是什么 | 为什么在这里而不是 contracts/ |
| --- | --- | --- |
| `pitfalls.md` | 反复踩到、代价高、且无法从局部代码看出的约束（含适用场景/失败表现/根因/规避/证据） | 是经验，不是系统现状；规则失效时会被删除或迁移 |
| `shading-model-case-records.md` | 论文 case 的逐条实测证据归档（像素/能量判据、复现命令、存档路径） | 是**已完成的实验记录**；`artifacts/` 被 gitignore，所以结论只能持久化在这里 |
| `../plan/**` | 在建的路线图、未开工的设计、已退役方案的记录 | 描述"打算做什么"，与"现在是什么"混在一起正是本仓库多次误读的根因 |
| `../plan/rendering/archive/**` | 主体已从仓库删除的文档（逐模型着色模型等），`archive/README.md` 写明每份为何在此、以及删除了什么 | 记录一次**刻意删除**的历史；明确不是契约 |

## 为什么把计划留在 `plan/` 而不并入这里

`plan/` 已经承担"在建 vs 未开工"的区分，且被 `AGENTS.md`、`README.md` 与门禁脚本按路径引用。
把它整体挪进 `rationale/` 只会制造一次无收益的大规模改路径。分层的目的已经达到：
**`documents/README.md` 明确写出 `plan/` 属于理性层，读者不会再把它当契约。**

## 关于本文档里的旧路径

`plan/` 与 `rationale/` 中的文档**保留写作当时的路径**（例如 `documents/rendering/xxx.md`、
`documents/architecture/yyy.md`）。这些目录已在 2026-10-11 的分层迁移中并入 `documents/contracts/`，
因此文中的路径引用可能指向**已不存在的位置**；其中一部分指向的文件本身就是被刻意删除的
（逐模型着色模型合同）。

这是历史记录的正常状态，不是待修的缺陷。**查找当前路径请用 `documents/routing.md`。**
只有 markdown 链接会被 `tool/validate-docs.py` 校验；纯文本路径引用不会被校验，因此也不会误报。

## 收录与升格

- 想固化为契约时，必须先把内容核对到当前源码/测试/门禁规则，再写进 `contracts/`，
  并在 `routing.md` 里给它一条源码路径路由。
- 一次性调试过程、提交时间线、已失效的尝试**不收录**：`git log` 才是它们的归档。
- 候选但未核实的经验写在 `pitfalls.md` 的"待确认候选"里，不得让实现默认依赖。
