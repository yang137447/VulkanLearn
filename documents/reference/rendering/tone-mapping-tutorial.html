游戏常用的 Tone Mapping 类型

游戏里的 tone mapping 通常不是单独一条 Reinhard 曲线。 更常见的是一套后处理收尾方案：HDR 画面先经过 bloom、曝光，再用 filmic / ACES 类曲线压到显示器能承载的范围。

Debug

Linear clamp

clamp(hdr, 0, 1)。正式画面几乎不用，但很适合看 HDR buffer 是否过曝、bloom 输入是否正常。

常见位置：debug view / capture view。 画面特征：高光被硬截断，颜色容易死白。
Tutorial

Reinhard

核心曲线是 L / (L + 1)。教程、demo、fallback 常见；正式游戏会嫌它偏灰、偏软。

常见位置：学习 renderer、临时方案。 画面特征：稳定但高光质感弱，推荐按亮度映射后还原 RGB。
Photographic

摄影式 Reinhard

引入 log-average luminance、middle gray、white point。重点不是曲线本身，而是让曝光有相机逻辑。

常见位置：自动曝光第一版。 画面特征：比固定曝光稳，但需要亮度统计。
Game

Filmic / Hable

用 toe 处理暗部、shoulder 处理高光。很多游戏会用这类曲线或它的变体作为项目风格基础。

常见位置：商业游戏、自研引擎。 画面特征：高光 roll-off 好看，可调性强。
Common

ACES fitted

游戏常用的是 ACES 近似拟合，不是完整 ACES 色彩管线。实现短、观感稳，非常适合当前项目作为默认。

常见位置：小引擎、学习 renderer、工具预览。 画面特征：高光舒服，中间调比 Reinhard 更有精神。
Art Control

Uchimura / GT

Gran Turismo 风格的分段曲线，把暗部 toe、中间线性段和高光 shoulder 拆开给美术控制。

常见位置：要求细调影调的实时项目。 画面特征：参数多，可单独塑造暗部、中间调和高光。
Modern

AgX / Display transform

更完整地把 tone mapping 当作从 scene-linear 到 display 的变换。适合色彩管理成熟后再做。

常见位置：长线渲染管线、DCC/引擎色彩管理。 画面特征：色彩压缩更自然，但工程概念更重。

Tone Mapping 公式速查

下面的公式默认输入 x 或 hdr 都是 linear HDR 值。 真正接 shader 时，推荐顺序是先合回 bloom，再曝光，再套曲线，最后输出 linear LDR。 标量曲线可以用于单通道或亮度，实际 RGB 应用方式要和“逐通道 / 亮度域”选择保持一致。

Linear clamp

只适合 debug。它不会保留高光层次，只是把超过 1 的值截掉。

vec3 LinearClamp(vec3 x)
{
    return clamp(x, 0.0, 1.0);
}

Reinhard

经典入门公式。推荐先映射亮度再按比例还原 RGB，尽量保持色度比例。

float Luminance(vec3 color)
{
    return dot(color, vec3(0.2126, 0.7152, 0.0722));
}

vec3 Reinhard(vec3 color)
{
    float luma = Luminance(color);
    float mappedLuma = luma / (luma + 1.0);
    return color * (mappedLuma / max(luma, 1e-5));
}

Extended Reinhard

增加 L_white 白点控制。降低白点会让高光更快爆白，升高则更保守。

float ReinhardExtendedLuma(float luma, float whitePoint)
{
    float w2 = whitePoint * whitePoint;
    return (luma * (1.0 + luma / w2)) / (1.0 + luma);
}

vec3 ReinhardExtended(vec3 color, float whitePoint)
{
    float luma = Luminance(color);
    float mappedLuma = ReinhardExtendedLuma(luma, whitePoint);
    return color * (mappedLuma / max(luma, 1e-5));
}

摄影式 Reinhard

先用 log-average luminance 做曝光，再用 white point 压缩亮度，适合自动曝光第一版。

float LogAverageLuminance(float logLuminanceSum, float pixelCount)
{
    return exp(logLuminanceSum / pixelCount);
}

// reduction pass:
// logLuminanceSum += log(0.0001 + Luminance(hdrColor));

float PhotographicReinhard(float Lw, float avgLum, float key, float whitePoint)
{
    float Lm = key * Lw / max(avgLum, 0.0001);
    float w2 = whitePoint * whitePoint;
    return (Lm * (1.0 + Lm / w2)) / (1.0 + Lm);
}

ACES fitted

当前项目推荐默认曲线。它是 ACES 风格的拟合近似，不是完整 ACES 色彩管线。

vec3 ACESFilm(vec3 x)
{
    const float a = 2.51;
    const float b = 0.03;
    const float c = 2.43;
    const float d = 0.59;
    const float e = 0.14;
    return clamp((x * (a * x + b)) / (x * (c * x + d) + e), 0.0, 1.0);
}

Hable / Uncharted

带 toe 和 shoulder 的 filmic 曲线。一般会用白点归一化，避免整体偏暗。

vec3 HablePartial(vec3 x)
{
    const float A = 0.15;
    const float B = 0.50;
    const float C = 0.10;
    const float D = 0.20;
    const float E = 0.02;
    const float F = 0.30;
    return ((x * (A * x + C * B) + D * E) /
            (x * (A * x + B) + D * F)) - E / F;
}

vec3 Hable(vec3 x)
{
    const vec3 whitePoint = vec3(11.2);
    return clamp(HablePartial(x) / HablePartial(whitePoint), 0.0, 1.0);
}

Uchimura / Gran Turismo

可配置分段曲线。下面是常见 GT 风格参数，按亮度映射可以更好保护色相。

float Uchimura(float x, float P, float a, float m, float l, float c, float b)
{
    float l0 = ((P - m) * l) / a;
    float S0 = m + l0;
    float S1 = m + a * l0;
    float C2 = (a * P) / (P - S1);
    float CP = -C2 / P;

    float w0 = 1.0 - smoothstep(0.0, m, x);
    float w2 = step(m + l0, x);
    float w1 = 1.0 - w0 - w2;

    float T = (m * pow(x / m, c) + b) / (1.0 + b);
    float L = m + a * (x - m);
    float S = P - (P - S1) * exp(CP * (x - S0));

    return T * w0 + L * w1 + S * w2;
}

vec3 UchimuraToneMap(vec3 color)
{
    float luma = Luminance(color);
    float mappedLuma = Uchimura(luma, 1.0, 1.0, 0.22, 0.4, 1.33, 0.0);
    return color * (mappedLuma / max(luma, 1e-5));
}

Exposure 和 EV100

曝光应该在 tone mapping 曲线之前。第一版可手动传 exposure，后续再换 EV100。

vec3 ApplyManualExposure(vec3 hdr, float exposure)
{
    return hdr * exposure;
}

float EV100(float aperture, float shutterSeconds, float iso)
{
    return log2((aperture * aperture) / shutterSeconds * 100.0 / iso);
}

float ExposureFromEV100(float ev100)
{
    return 1.0 / (1.2 * exp2(ev100));
}

Bloom、Saturation、sRGB

这些不是 tonemap 曲线本身，但基本都会和 tone mapping pass 放在一起。

vec3 ComposeBloom(vec3 scene, vec3 bloom, float bloomStrength)
{
    return scene + bloom * bloomStrength;
}

vec3 ApplySaturation(vec3 color, float saturation)
{
    float luma = dot(color, vec3(0.2126, 0.7152, 0.0722));
    return mix(vec3(luma), color, saturation);
}

vec3 LinearToSrgb(vec3 x)
{
    vec3 lo = x * 12.92;
    vec3 hi = 1.055 * pow(max(x, vec3(0.0)), vec3(1.0 / 2.4)) - 0.055;
    return mix(lo, hi, step(vec3(0.0031308), x));
}

注意：如果 Vulkan swapchain / render target 是 *_SRGB， shader 通常输出 linear LDR 即可，让硬件在写入时做 sRGB encode。 只有输出到 UNORM 非 sRGB target 时，才需要自己调用 LinearToSrgb。

快速对比与选择指南

方法 风格 参数数量 色度处理方式 适合场景
Reinhard Extended 自然、略灰 1 个白点 亮度比例映射 快速原型、科学可视化、fallback
Hable Filmic 电影感、高对比 通常固定 6 个参数 逐通道 浓烈电影风、需要强 shoulder 的游戏
Narkowicz ACES 现代中性电影感 0 逐通道 PBR renderer、引擎默认 tone mapper、入门首选

逐通道处理

Hable、ACES 这类通常直接处理 RGB。高亮区域可能会发生饱和度变化或自然消色， 但这也经常被接受为 filmic 观感的一部分。

亮度域映射

Reinhard、Uchimura 常见做法是先映射亮度，再按比例还原 RGB。 它更保护原始色相，但极端高饱和颜色可能超出显示色域，需要 clamp 或后续色域映射。

学习路径建议

先手写 Narkowicz ACES 感受现代默认效果，再对比 Hable Filmic 和 Reinhard。 最后实现 Uchimura，调节 m、c、l 等参数， 建立暗部、中间调和高光分段塑形的直觉。

游戏一般真正用什么

最常见的默认路线是 Filmic / ACES 系 tonemapper + 手动或自动曝光 + LUT 调色。 曲线负责把 HDR 压进显示范围，曝光负责整体亮度，LUT 或 color grading 负责项目风格。

1 Linear HDR Lighting PBR、阴影、IBL、天空、emissive 都写入 FP16 HDR buffer。
2 HDR Post Effects SSR、体积光、DOF 等需要场景亮度的效果在 tone mapping 前做。
3 Bloom 从 HDR scene color 取亮部，模糊后按强度加回。
4 Exposure 手动曝光、EV100 或自动曝光，把画面放到合理亮度区间。
5 Filmic Curve ACES、Hable、AgX 或项目自定义曲线，处理高光肩部和暗部 toe。
6 Display Output 输出到 sRGB swapchain 或 HDR display path。UI / debug overlay 通常在 tone mapping 后叠加。

对 VulkanLearn 这种学习 renderer，推荐先别做过重的色彩管理。 先实现 ACES fitted + manual exposure + bloomStrength，同时保留 Linear clamp debug 模式。 这条路线最短、观感提升最明显，也方便以后升级自动曝光和 LUT。

推荐路线：先做一条稳的游戏默认链

这条路线的目标不是最“影视工业”，而是最适合 VulkanLearn 当前阶段： 改动小、能快速改善观感、每个参数都有清楚职责，后续还能自然升级。

1

所有光照先进入 linear HDR

geometry、sky、IBL、emissive 都应该写进 FP16 scene color。 这里不要做 gamma，也不要提前压到 0-1。你的 sceneColor 和 bloom buffer 用 R16G16B16A16_SFLOAT 是对的。

albedosRGB 采样
normal / ORMlinear 采样
sceneColorFP16 HDR
swapchainsRGB 输出
2

Bloom 在 tone mapping 前提取和合回

Bloom 应该从 HDR scene color 提取亮部，再 downsample / blur / upsample，最后在 tone mapping pass 里合回。 不要用 bloom 去“补亮画面”，它只负责高亮溢出。

threshold1.0 - 1.2
knee0.3 - 0.5
strength0.05 - 0.10
debug可临时设 0
3

第一版先用手动 exposure

手动 exposure 是最便宜也最清楚的虚拟相机。它只管整体明暗，不管风格。 等场景亮度更稳定后，再做 EV100 或 histogram auto exposure。 

vec3 hdr = sceneColor + bloomColor * bloomStrength;
vec3 exposed = hdr * exposure;
4

默认曲线用 ACES fitted

它比裸 Reinhard 更像游戏默认画面：中间调不那么灰，高光压缩也更自然。 先把它作为默认，再保留 Reinhard / Linear clamp 作为对照和 debug。 

vec3 color = ACESFilm(exposed);
5

色彩风格放到 saturation / LUT

Tonemapper 不是万能调色台。默认曲线稳定后，再用 saturation、contrast 或 3D LUT 做美术风格。 当前项目第一版可以先加 saturation，LUT 等以后再做。

6

最后输出到 sRGB swapchain

如果实际 swapchain 是 sRGB 格式，tone mapping shader 输出 linear LDR 就够了。 不要再手写 pow(color, 1.0 / 2.2)，否则可能双重 gamma。UI / debug overlay 通常在 tone mapping 后画。

推荐路线后续怎么升级

阶段 A：手动曝光

第一版推荐直接用一个 exposure 参数。 它不是风格参数，而是虚拟相机的曝光补偿。先把这个调通，画面会立刻比固定值好控。 

vec3 hdr = sceneColor + bloomColor * bloomStrength;
vec3 exposed = hdr * exposure;
vec3 ldr = ACESFilm(exposed);

阶段 B：EV100 相机模型

如果场景光照单位逐渐稳定，可以把曝光做成摄影参数：光圈、快门、ISO。 这更像真实相机，但前提是场景亮度别完全靠玄学填数。 

float ev100 = log2(aperture * aperture / shutterSpeed * 100.0 / iso);
float exposure = 1.0 / (1.2 * exp2(ev100));
vec3 exposed = hdr * exposure;

阶段 C：自动曝光

自动曝光通常会先生成 luminance mip chain 或 histogram，然后把平均亮度拉到 middle gray。 这是后续升级项，不建议在 tone mapping 还没稳定时先做。 

float targetGray = 0.18;
float exposure = targetGray / max(logAverageLuminance, 0.0001);

进阶：局部色调映射

前面的 Reinhard、Hable、ACES、Uchimura 都是全局算子：所有像素共用同一条曲线。 当场景亮度跨度极大，比如室内看向窗外，局部算子可以更好保留暗部和窗外高光。

Reinhard 摄影减淡与加深

思路是把图像转到对数亮度域，用不同半径的模糊估算每个像素的局部适应亮度， 再根据局部亮度动态压缩。它能模拟摄影里的 dodging / burning，但计算量和调参复杂度都更高。

现代实时替代

双边滤波、引导滤波、局部 histogram 或基于 mip chain 的 exposure 都可以作为实时替代。 关键是避免局部对比增强产生光晕和边缘脏影。

对 VulkanLearn 的建议

暂时别急着做局部 tone mapping。先把全局 ACES、手动曝光、bloomStrength 和 DebugConsole 调参链路稳定下来。 等有室内外强亮度差场景，再考虑 histogram auto exposure 或局部适应。

接入 VulkanLearn 的推荐版本

这里把上面的推荐路线翻译成当前仓库里的实际改动点。 第一版只需要动 tone mapping shader 和 pass material 参数，bloom prefilter 的阈值可以作为第二步再参数化。

  • 保留当前 pass 顺序。 geometry + sky -> postProcess -> bloom -> toneMapping -> swapChain 这条结构是对的，问题主要在最后 shader 太简。
  • 给 tone mapping pass 加材质参数。 最小参数是 u_toneMappingParams = vec4(exposure, bloomStrength, saturation, mode)。
  • 默认 mode 选 ACES fitted。 0 做 debug linear，1 用 ACES 默认，2 Reinhard 对照，3 Hable 风格参考；Uchimura 等美术参数需求明确后再加。
  • 不要手写 gamma。 如果最终 surface 是 sRGB 格式，shader 输出 linear LDR，硬件写入时会 encode。
  • bloomStrength 先从 0.08 开始。 当前 1.0 适合作为 debug 上限，不适合作为默认审美值。 
layout(set = 1, binding = 0) uniform UBOMIParamters {
    vec4 u_toneMappingParams;
};

float exposure = u_toneMappingParams.x;
float bloomStrength = u_toneMappingParams.y;
float saturation = u_toneMappingParams.z;
float mode = u_toneMappingParams.w;

vec3 hdr = scene + bloom * bloomStrength;
vec3 exposed = hdr * exposure;
vec3 color = ApplyToneMap(exposed, mode);
color = ApplySaturation(color, saturation);
outColor = vec4(color, 1.0);

推荐最小 GLSL 结构

float Luminance(vec3 color)
{
    return dot(color, vec3(0.2126, 0.7152, 0.0722));
}

vec3 LinearClamp(vec3 x)
{
    return clamp(x, 0.0, 1.0);
}

vec3 Reinhard(vec3 color)
{
    float luma = Luminance(color);
    float mappedLuma = luma / (luma + 1.0);
    return color * (mappedLuma / max(luma, 1e-5));
}

vec3 ACESFilm(vec3 x)
{
    const float a = 2.51;
    const float b = 0.03;
    const float c = 2.43;
    const float d = 0.59;
    const float e = 0.14;
    return clamp((x * (a * x + b)) / (x * (c * x + d) + e), 0.0, 1.0);
}

vec3 HablePartial(vec3 x)
{
    const float A = 0.15;
    const float B = 0.50;
    const float C = 0.10;
    const float D = 0.20;
    const float E = 0.02;
    const float F = 0.30;
    return ((x * (A * x + C * B) + D * E) /
            (x * (A * x + B) + D * F)) - E / F;
}

vec3 Hable(vec3 x)
{
    const vec3 whitePoint = vec3(11.2);
    return clamp(HablePartial(x) / HablePartial(whitePoint), 0.0, 1.0);
}

vec3 ApplyToneMap(vec3 color, float mode)
{
    if (mode < 0.5) return LinearClamp(color);
    if (mode < 1.5) return ACESFilm(color);
    if (mode < 2.5) return Reinhard(color);
    if (mode < 3.5) return Hable(color);
    return ACESFilm(color);
}

vec3 ApplySaturation(vec3 color, float saturation)
{
    float luma = dot(color, vec3(0.2126, 0.7152, 0.0722));
    return mix(vec3(luma), color, saturation);
}

调试顺序

1. 先关 bloom

把 bloomStrength 设为 0。确认纯 scene HDR 经过 exposure + tonemap 是否舒服。

2. 调 exposure

让主体材质落在合理亮度，别先靠 bloom 或 saturation 救画面。

3. 再加 bloom

从 0.05 慢慢加，直到高光有呼吸感但不糊成白雾。

4. 查颜色空间

albedo / emissive 用 sRGB 采样，normal / roughness / metallic / AO 用 linear。这个项目的 texture JSON 已经有 colorSpace 字段，应继续保持。

5. 最后才调风格

风格最好放到 saturation、contrast、LUT 或 color grading。Tonemapper 先稳定，不要让它承担所有审美职责。
