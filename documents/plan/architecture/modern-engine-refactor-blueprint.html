1) 重构目标

这次重构不是“代码美化”，而是建立长期可维护的系统边界：场景切换不再跨模块散射修改、资源生命周期明确、渲染系统可以按职责增量升级。

Scene 生命周期可重入 渲染前后端解耦 资源 owner 明确 事务化切换可回滚

2) 当前痛点（为什么会“改一处动全局”）

生命周期入口分散

加载场景、绑定相机、渲染初始化分布在不同点位，缺少统一切换事务入口。

SceneLoader 职责过多

同时承担 JSON 解析、运行时对象构建、环境预处理、Pass 材质准备，耦合面过大。

初始化模型偏“一次性”

多个系统默认只初始化一次，导致 reload 时需要手工穿透式修补。

全局访问链路重

GetInstance() 直接跨层访问，让依赖方向很难稳定。

4) 场景切换事务图（核心机制）

目标是让 scene load/reload 变成可回滚事务，而不是“局部成功、全局半失效”。

5) 现有模块到目标模块映射

当前模块 问题 目标归属
main.cpp 直接串所有生命周期步骤 EngineLoop + SceneTransitionCoordinator
SceneLoader 解析/构建/渲染准备混在一起 SceneAssetResolver + SceneRuntimeBuilder
RenderSystem 初始化与运行态切换边界不清 RenderFrontend + OnSceneChanged API
RenderGraph Descriptor 和 pass 生命周期耦合偏重 FrameGraphCompiler + PassRuntime
LightManager 默认一次性初始化 Scene-bound GPU buffer service

6) 分阶段迁移（建议顺序）

Phase A：生命周期基座

目标：建立统一事务入口，不改渲染算法。

动作：先把场景切换集中到 Coordinator。

Phase B：Scene 领域拆分

目标：SceneLoader 职责拆开，形成 RuntimeBuilder。

动作：Asset/Runtime 数据结构分层。

Phase C：渲染前后端解耦

目标：RenderFrontend 产出 RenderWorld，Backend 只提交。

动作：按层收口依赖，减少跨层单例访问。

Phase D：性能与并行

目标：异步资源上传、缓存命中、并行任务化。

动作：在边界稳定后再做并发化。

7) 第一阶段验收标准

  • 场景切换入口只有一个事务接口（控制台/UI 仅发请求）。
  • 连续切换 5 次不同场景无崩溃，无黑屏，输入控制正常。
  • 切换失败可回滚到旧场景，不进入半失效状态。
  • 全局资源与场景资源生命周期边界可追踪。
