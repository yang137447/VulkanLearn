## 1. 已确认的方向

- 动画状态机在 C# 完成，包括状态、进入/退出、转移条件、优先级、中断与行为选择。
- C++ 提供通用姿态执行能力：采样、混合、分层、曲线、IK、姿态发布与 GPU 蒙皮。
- 优先建设动画预览和可视化调试；节点式动画蓝图编辑器不进入首版交付。
- 第一交付目标为单机、单套固定骨架、单角色的核心移动体验。
- ALS 指 Advanced Locomotion System。具体使用原版 V4、Community 还是 Refactored
  作为对照尚未锁定，必须在 P0 固定来源与 revision，不能混合不同版本的行为定义。
- 本计划的“核心版本”是明确的功能子集，不宣称完整兼容 UE 动画蓝图或完整复现 ALS。

## 3. 首版范围

### 核心版本包含

- 骨架、蒙皮网格、动画片段及浮点曲线/事件的正式资产加载。
- 原地待机、走、跑、冲刺、方向混合、起停，以及匹配资产支持的原地转身。
- 移动朝向与观察朝向模式、跳跃/下落/落地、蹲伏及安全站起。
- 动画循环相位同步、交叉混合、基础骨骼遮罩与叠加姿态。
- 双脚 IK、骨盆高度修正、脚锁定，以及斜坡/台阶上的调试显示。
- 预览播放、暂停、拖动时间轴、逐采样帧、参数调整和运行时状态检查。
- 单/双线程渲染、生命周期、程序集换代、资源闭包导出与静态网格兼容。

### 后续扩展

Root Motion 驱动移动、翻越、翻滚、布娃娃及起身、复杂武器姿态组合、
任意骨架重定向、联网预测/同步、多角色规模优化和完整节点编辑器单独排期。
首版可检查根轨道，但不以根轨道直接移动物理角色；不支持的请求明确拒绝。
动画事件首版提供有界值事件及调试显示，不承诺音频、粒子系统。

## 4. 归属与执行边界

### 4.1 C# 拥有状态机

通用状态机支撑放在常驻 Runtime；具体 ALS 控制器与角色调参源码放在资源仓库。
Grounded/InAir 等状态、步态、姿态、朝向、切换优先级和中断规则都由 C# 决定。
C++ 不再维护一套同名 ALS 状态机，也不根据速度自行选择下一个业务状态。
资产中的 BlendSpace、曲线和骨骼遮罩只描述姿态与采样数据，不承载业务转移条件。

优先以现有逻辑组件承载控制器，不先增加一套独立的托管宿主或动画脚本程序集。
状态/层/播放实例使用稳定 ID；不得用 CLR 对象地址、委托或枚举序号作为持久身份。
每次状态更新最多提交一次已决转移；优先级相同按明确的声明顺序处理，
不在同次更新中无界连跳。转移窗口、退出条件和中断规则需要独立测试。

### 4.2 原生侧拥有姿态执行

拟提供片段采样、1D/2D 混合、同步组、分层遮罩、叠加、曲线采样与双骨 IK。
优先验证成熟动画库，避免从零重写整个采样/混合数学底座；
P0 对 ozz-animation 做 MinGW/C++17 与真实片段验证后再锁定依赖。
BlendSpace 配置、曲线/事件和 GPU 蒙皮仍需自己的集成，不假定选库便自动具备。

C# 在初始化时声明可复用的姿态组合，逐帧仅提交数值参数与播放/过渡请求；
不逐帧重建整张姿态图，不跨现有 JSON 桥接传骨骼矩阵或逐骨委托。
动画数据入口校验骨架兼容性、有限值、索引、时间、权重及预算，
已发布运行时数据不在 shader 中重复修补。

片段播放时钟与淡入淡出的数值进度由原生播放器唯一维护，C# 根据其只读反馈
决定是否继续、结束或中断。这是执行反馈，不是第二份状态机。
转移时不连续重置播放器；同值参数与新的播放请求通过请求 ID 区分。
纯预览的 seek 不触发游戏事件，循环/跨越多个事件的顺序、去重和上限必须明确。

### 4.3 帧顺序

首版保留已有脚本/物理顺序，在其后接姿态求值：

1. C# Tick 读取输入并产生移动意图。
2. FixedTick 与 Jolt 子步交替执行，实际位姿、速度与着地状态回传。
3. 交付既有接触与查询回调；C# LateTick 根据物理反馈更新动画状态和参数。
4. 完成现有 LateTick 后的零时步同步，冻结本帧动画输入。
5. 原生执行采样、混合及当前物理世界上的受控足部探测/IK，冻结姿态与调试值。
6. 发布 World/UI 快照；RT 只读快照并上传 palette，不访问 CLR 或活动 World。

动画播放反馈与事件在下一次受控 C# 更新前交付，不在姿态求值中递归调用脚本。
不得将 LateTick 发出的异步查询误当作本帧可用结果；
足部探测使用明确的原生物理阶段，不让动画 worker 直接读写 Jolt。
首版姿态 CPU 求值在 GT，后续是否移到 worker 由测量决定。
Pause 和 TimeScale=0 不推进播放时间、淡入淡出和游戏动画事件；
编辑器的显式预览 seek 使用独立会话时钟。

### 4.4 物理与渲染

核心移动由 Jolt 最终碰撞结果决定，动画速度取实际运动，不仅取输入期望速度。
站立/蹲伏保持脚底基准，站起先做形状可容纳检测，顶棚阻挡时保留蹲伏。
不得只缩放视觉模型来模拟胶囊蹲伏；根统一缩放的现有约束继续保留。

蒙皮优先独立输入流/变体，避免所有静态网格永久增加骨骼属性开销。
主画面与 ShadowDepth 共享同一姿态与蒙皮数学；法线、切线和 handedness 一并验证。
动画 bounds 必须覆盖实际变形，不能沿用静态绑定姿态 bounds 导致剔除/取景错误。
速度输出使用当前姿态与“上一次实际提交渲染”的姿态；
单最新快照可能丢弃 GT 帧，不能把上一 GT 帧直接当上一已渲染帧。
首帧、传送、Stop 与 World 换代明确重置历史。
palette/buffer、资源引用和旧 descriptor 沿现有 GPU epoch 退休，不能覆盖在途帧数据。

## 5. 分阶段交付

所有阶段当前均未实施。每个阶段完成后补证据、更新对应当前契约，
不能只在本计划勾选后便宣称运行时已经支持。

| 阶段 | 交付内容 | 完成门槛 | AI 有效执行时间粗估 |
| --- | --- | --- | ---: |
| P0 基线与资产 | 锁定 ALS 对照版本、角色骨架、片段清单、依赖与坐标规范 | 一套资产可导出；关键曲线/同步标记/IK 骨映射完整；MinGW 依赖验证通过 | 2～4 小时 |
| P1 动画资产 | 骨架、权重、绑定矩阵、片段/曲线/事件导入与校验 | 绑定姿态还原、参考帧和跨 section 对照通过；坏资产拒绝发布 | 4～6 小时 |
| P2 蒙皮闭环 | palette、快照、主画面/阴影、bounds 与姿态历史 | 真实角色播放一个片段；阴影同步；静态模型回归和单/双线程通过 | 6～10 小时 |
| P3 C# 状态机 | 通用支撑、控制 API、反馈/事件与 Idle/Move/InAir | C# 可控制待机/走跑/跳跃；可中断混合；Pause/Stop 与失败隔离通过 | 4～8 小时 |
| P4 移动与混合 | 步态/方向混合、相位、加减速、朝向、起停转身、蹲伏 | 固定动作矩阵通过；撞墙动画回落；顶棚下不能站起 | 8～12 小时 |
| P5 预览与调试 | RmlUi 动画面板、时间轴、曲线/状态/权重和骨架显示 | 独立预览可 seek/步进；运行时检查不改变脚本状态；焦点/窗口布局通过 | 4～8 小时 |
| P6 足部质量 | 双脚 IK、骨盆修正、脚锁定与解锁规则 | 平地/斜坡/台阶、转身/起跳/落地和传送重置对照通过 | 8～14 小时 |

| 合计 | 核心版本，包含调试工具与集成 | 按阶段重新校准 | 42～72 小时 |

这里是 AI 主导实现、构建、测试和修复的有效执行时间估计，不是已有吞吐实测。
按约 25% 返工余量预留 **53～90 小时**；日历时间约 **2～3 周**，
取决于资产准备、构建环境、交互验收和每日实际推进时间。
资产制作、导出工具不可用、缺失片段补做以及后续扩展不包含在这个范围内。
此前“12～24 小时”的最小演示估计不作为本计划带完整生命周期验收的工期承诺。
P0 结束、P3 走跑闭环结束分别重估，不为了守住估计省略验证。

### P0：先消除未知项

- 记录参考版本与所需片段/曲线/事件/同步标记，不只拿一个角色 FBX 便开始移植。
- 确认源码和内容的来源、可获取性与使用范围；没有选定资产就不宣称 ALS 兼容。
- 最小资产集包含 Idle、Walk、Run、Jump/Fall/Land；核心完整集补方向、冲刺、
  蹲伏、起停转身与足部曲线。缺失项记录为阻塞该功能，不用占位动画冒充完成。
- 核对源坐标、手性、前向、单位、root/pelvis、IK/虚拟骨和动画根轨道。
  统一骨架、网格、inverse bind 与 clip 的变换，测量现有 Assimp/World 的单位转换，
  不仅依据导入注释推断；厘米世界与 Jolt 米制转换只在既有物理边界处理。
- 验证 ozz 候选的构建与一段真实动画；固定 commit/摘要，隔离第三方构建选项。
- 查明骨骼 palette 的 descriptor、shader 变体和热重载 ABI 影响，
  再决定具体绑定，不在计划里提前占用某个 binding。

### P1～P3：首个纵向闭环

先完成绑定姿态和单片段蒙皮，再接 C# Idle/Move/InAir，不先铺开全部 ALS 行为。
P1 对权重数量/归一化、无权重顶点、缺轨道默认姿态和骨架签名作明确约定；
MikkTSpace 拆分/重排顶点时必须同步保留权重，不能导入后按旧顶点索引回填。
源资产解析与转换走正式资源加载，不建立第二套只供 demo 使用的模型导入器。

P2 采用小型可解析骨架数值夹具与真实角色双重验证，检查位置、法线、切线、
section 局部变换和阴影；静止、原地动画、根整体移动分别核对速度输出。
P3 提供有界参数/请求批次、播放反馈和事件，非法 ID、过期上下文或失败回调
不得发布半套参数；不要求回滚任意用户 C# 字段，沿用现有故障隔离边界。
最小状态/播放时间检查随 P3 交付，不等 P5 才具备诊断能力。

验收场景为拟新增 `Maps/SC_als_locomotion/SC_als_locomotion.json`，
中文 description 明确它是角色移动/动画学习与回归场景，不是论文验证。
到 P3 应能用同一正式场景观察待机、走跑、跳跃、阴影以及 Play/Pause/Stop。

### P4～P6：核心观感

P4 先固定直行/斜行/倒退、走跑切换、突然反向、撞墙、落地与蹲伏矩阵。
原地转身与移动方向偏移区分角色根朝向和视觉骨盆偏移，避免相机、胶囊和动画
各自重复施加一次旋转。循环混合验证脚步相位，不能只插值两个 clip 的时间秒数。
骨骼遮罩与叠加姿态至少做一条实际可见路径，不能只有未消费的 API。

P5 区分两种会话：片段预览只执行原生动画求值，不启动 Blueprint/物理；
运行时检查跟随选中角色，仅提交受控调试命令。不能在现有 BP 预览中偷偷启动 C#。
预览 seek/逐采样帧先暂停本会话，不推进关卡；运行时单步游戏留待专门设计。
临时调参仅修改调试覆写，显式保存前不写作者资产，窗口关闭清理会话。
面板消费冻结值，控件只产生值命令，按 generation/实例 ID 验证目标。

P6 的足锁基准空间、骨盆位移空间、坡面法线与脚朝向必须有中文注释与测试。
传送、起跳、owner 禁用、Stop、World 换代和骨架变化均重置不适用的锁定。
移动平台正确性单独记录；若未完成平台空间锁定，不将静态地面的通过扩大为平台支持。

### P7：完成的含义

验证 Spawn/Destroy、组件移除重建、Pause/Stop、World 成功/失败替换与 GPU 退休。
动画资产纳入正式依赖闭包、异步 BP 资源准备和游戏导出，不靠开发机绝对路径运行。
不得凭导出程序退出成功认定包可用；需实际从独立包启动并核对动画。

程序集重载分两层处理：C# 仅显式迁移稳定状态值；原生播放器不保存 CLR 引用。
拟在候选阶段按稳定 ID/骨架签名验证状态、层和播放绑定，成功后一起交换，
失败保留旧程序集与原生播放状态。不能在受限 OnReload 中直接调用动画播放来补状态。
若这一集成未完成，应明确拒绝相应播放中重载，不能静默重置动画并标为完整交付。

## 8. 后续扩展的前置条件

Root Motion 驱动与翻越需要新增“固定步提取位移 → Jolt 碰撞求解 → 实际位移反馈”
的单一消费路径，不能在 LateTick 直接改根位置绕过碰撞，也不能和普通 Move 重复移动。
布娃娃需要逐骨刚体、约束与动画/物理姿态转换，不由现有根刚体支持自动推得。
重定向、联网和节点编辑器分别立项；首版稳定 ID、参数描述和调试快照可供它们复用，
不提前实现一个无人使用的通用节点编辑框架。
