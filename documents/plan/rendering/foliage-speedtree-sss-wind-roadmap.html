Foliage / SpeedTree / SSS / Wind 落地路线

这份 HTML 规划把第一棵 SpeedTree 树接入 VulkanLearn 的路线拆成可验收阶段：先补模型内多 mesh / 多材质导入，再做静态树显示、叶片 alpha cutout 和薄表面透射，随后加入全局风、SpeedTree 风数据评估和 multi-pivot。目标是先得到一棵结构正确、能显示、能透光、能动的树，再逐步靠近完整植被系统。

Windows / Vulkan / C++17 Data-driven scene Foliage transmission first Wind in vertex shader Multi-pivot after data exists

官方资料核对

能直接借鉴的部分

  • SpeedTree Compiler 官方说明支持把树导出为静态 mesh 格式，默认包含 OBJ 和 FBX 路线，也提到可开发自定义 mesh exporter。
  • Modeler 的 VFX Wind 文档明确了风来自 Fan object 和各 generator 的 wind 属性，建议先跑 Wind Wizard 再细调。
  • 官方风文档把 branch wind 分成共享 motion 和最多四个离散 branch wind level，leaf wind 则分成两个 leaf group。
  • SDK 文档的 render configuration 是多 render pass 思路，示例中有 Forward、Depth Only、Deferred，并能按 LOD 与 geometry type 选择 shader/state。
  • SDK 性能文档明确风主要压在 vertex shader，风效果可以按 Full、Branch、Global、None 做 LOD。

不能直接照搬的部分

  • SDK 路线围绕 .stsdk、Render Interface、reference app 和平台 render policies，当前 VulkanLearn 更适合先走 FBX/GLB 静态资产接入。
  • 官方 VFX Wind 对 FBX/Alembic 的风导出更偏离线动画缓存，不等价于实时游戏 shader 风数据。
  • 完整 SpeedTree shader 含大量 LOD、billboard、vertex packer 和产品化宏，第一版不应该直接搬进学习 renderer。
  • multi-pivot 必须来自导出或转换数据。官方资料能指导分层概念，但不能替代我们自己的 vertex layout。

结论：第一轮采用“多 section 静态 mesh + 自己的 foliage shader + 自定义 wind/pivot 数据”的接入路线；官方 SDK 文档作为结构参考，不作为第一版依赖。

接入策略

第一步建立 source/mesh/ 文件夹，并新增 MeshAssetResolver 与 MeshAssetValidator，模仿 material 的 loader / validation 分层。
第二步迁移 mesh asset JSON 到必填 materialSlots，旧 materialInstancePath 直接报错。
第三步迁移 ModelLoader 到 source/mesh/loader/，并让它返回完整 ModelResource。
第四步建立 section material slot -> material instance 映射，让一棵树以一个模型资源进入场景。
第五步叶片先走现有 pbr + OpaqueClip + cullMode=None，确认 alpha、normal、shadow 基础链路。
第六步新建 foliage shader，再加入全局 wind 和后续 SpeedTree 风数据评估。

下一步：materialSlots

materialSlots 是下一块最该先做的格式迁移。它把模型文件里的材质槽名称映射到 VulkanLearn 的 material instance JSON，让一个 SpeedTree 模型可以在同一个 mesh asset JSON 里绑定树干、树枝、叶片等多个材质。迁移后不再支持旧的 materialInstancePath。

模块边界

  • SceneLoader 只负责编排 scene object 和创建 renderable sections。
  • source/mesh/meshAssetTypes.h 放 mesh asset 数据结构。
  • MeshAssetResolver 位于 source/mesh/loader/，对齐 material resolver。
  • MeshAssetValidator 位于 source/mesh/validation/，提供 BuildLoadPlan() 和 BuildSectionLoadPlans()。
  • ModelLoader 位于 source/mesh/loader/，只导入 FBX / GLB / OBJ 几何和材质槽名。
  • 新增 mesh 类头文件遵循 documents/architecture/coding-guidelines.md 的职责注释规则。

调用链

SceneLoader
  -> read SM_*.json
  -> MeshAssetResolver
  -> MeshAssetValidator::BuildLoadPlan()
  -> ModelLoader
  -> MeshAssetValidator::BuildSectionLoadPlans()
  -> LoadMaterialInstance()

头文件注释：通用规则放在 documents/architecture/coding-guidelines.md。本模块里，MeshAssetResolver 说明 effective mesh asset JSON 的展开边界；MeshAssetValidator 说明 load plan 构建、格式验证和错误输出边界；ModelLoader 说明只导入 geometry sections 与 material slot 名，不认识 VulkanLearn material instance JSON。

.stsdk 入口：SpeedTree .stsdk 仍然通过 SM_xxx.json 引入。scene object 只写 modelPath，mesh asset JSON 保持现有平铺风格，用 type: "speedtree" 和 modelDataPath 指向 .stsdk。第一版不写 importCache，数据都直接从 .stsdk 解析出来。

阶段计划

阶段 0：资产约定与最小测试场景

准备

建立 scene_foliage_test.json，第一棵树放到外部资源目录，并明确 SpeedTree 导出文件里的 mesh section 与 material slot 命名。

验收

  • 启动能加载 foliage 测试场景。
  • 测试资产的 section / slot 名称明确。
  • 路径全部指向外部资源树。

阶段 1：多 mesh / 多材质导入地基

模型系统

先按 material 风格建立 source/mesh/，把 ModelLoader 一起迁进 source/mesh/loader/，再升级 scene loading，让一个 SpeedTree 文件保留多个 mesh section 和材质槽。后续材质、shadow、wind 都建立在这个真实结构上。

  • source/mesh/meshAssetTypes.h 定义 asset/load plan 数据结构。
  • MeshAssetResolver 位于 source/mesh/loader/。
  • ModelLoader 位于 source/mesh/loader/。
  • MeshAssetValidator 位于 source/mesh/validation/。
  • ModelResource.sections[] 保存 section geometry。
  • materialSlotName 映射到材质实例 JSON。
  • loader 可展开成多个内部 scene object，或一个 scene object 持有多个 renderable part。

验收

  • 一个模型文件显示多个部分。
  • 每个 section 绑定自己的 material instance。
  • 普通旧模型迁移到 materialSlots 后仍可加载。
  • 错误信息能指出缺失的 section 或 material slot。

阶段 2：静态树导入与叶片 alpha

可见成果

基于阶段 1 的 material slot 映射，树干用普通 PBR opaque，叶片用 PBR alpha cutout。先证明贴图、切线、UV、双面和 shadow 轮廓是对的。

  • MI_speedtree_trunk.json：renderMode=Opaque
  • MI_speedtree_leaf.json：renderMode=OpaqueClip，cullMode=None
  • u_alphaClipThreshold 作为独立 alpha clip threshold

验收

  • 叶片不是矩形 card。
  • 叶片双面可见。
  • normal map 没有明显方向错误。
  • shadow pass 中叶片轮廓可接受。

阶段 3：Foliage shader 与薄表面 SSS

Shading

新增 foliage.vert、foliage.frag 和 foliageLighting.glsl。SSS 第一版只做树叶薄表面透射，不做屏幕空间 blur。

UBOMIParamters:
  vec4 u_tintColor;
  vec4 u_pbrFactors;        // roughness, metallic, ao, reserved
  float u_alphaClipThreshold;
  vec4 u_transmissionColor; // rgb color, a strength
  vec4 u_foliageFactors;    // wrap, backPower, normalBlend, shadowTransmission
  float u_emissiveStrength;

验收

  • 顺光时不整体发亮。
  • 逆光时叶片边缘和薄片区域透亮。
  • transmission strength 归零后接近普通 PBR。

阶段 4：Foliage shadow 对齐

阴影

增加 foliage shadow shader，shadow pass 做相同 alpha discard。后续 wind deformation 也必须被 shadow pass 复用。

  • foliageShadow.vert
  • foliageShadow.frag
  • common/foliageWind.glsl

验收

  • 阴影不是整张叶片 card。
  • alpha threshold 与主 pass 一致。
  • 后续风动时树影同步。

阶段 5：全局 Wind 与简单顶点风

Wind V1

先建立工程自己的风入口。第一版只做高度或 vertex color 驱动的树冠摆动，让树明显活起来。

WindParameters:
  vec4 directionStrength; // xyz direction, w strength
  vec4 timeFrequency;     // time, trunk, branch, leaf
  vec4 gust;              // strength, frequency, scale, reserved
  vec4 bend;              // trunk, branch, leaf, reserved

验收

  • 树干基本不动，树冠明显摆动。
  • 风向、强度、频率可调。
  • strength=0 回到静态树。

阶段 6：SpeedTree 风数据评估

数据边界

检查 SpeedTree 导出文件实际保留了哪些信息：vertex color、额外 UV、custom attribute、pivot、branch id、leaf group。只接入能被 Assimp 或转换工具稳定读到的数据。

验收

  • 普通 mesh 不受 foliage layout 影响。
  • foliage shader 能读取 wind0/wind1/wind2。
  • 无 wind 数据资产可生成默认值。

阶段 7：Multi-Pivot 基础变形

Pivot

branch sway 围绕 primary pivot，leaf flutter 围绕 leaf 或 secondary pivot。pivot 必须来自资产或转换结果，不在 shader 里按位置硬猜。

RotateAroundAxis(positionOS, pivotOS, axisOS, angle)

验收

  • 枝条围绕合理根部摆动。
  • 叶片 flutter 不脱离枝条。
  • 主 pass 与 shadow pass 同步。

数据设计

第一轮不要全局替换现有 Vertex。更稳的路线是让 pipeline state 支持不同 vertex layout，普通 mesh 继续使用 Vertex，foliage mesh 使用 FoliageVertex。

struct FoliageVertex
{
    Eigen::Vector3f position;
    Eigen::Vector3f normal;
    Eigen::Vector3f color;
    Eigen::Vector2f texCoord0;
    Eigen::Vector4f tangent;
    Eigen::Vector4f wind0; // branchWeight, leafWeight, phase, stiffness
    Eigen::Vector4f wind1; // primaryPivotOS.xyz, pivotWeight
    Eigen::Vector4f wind2; // secondaryPivotOS.xyz, hierarchyLevel
};

Foliage Shading

第一版光照组成

  • front diffuse/specular：从当前 PBR direct lighting 拆出来。
  • back transmission：根据 dot(-N, L)、透射颜色、强度和贴图增加逆光透亮。
  • indirect lighting：继续使用 SH diffuse IBL 与 prefiltered specular IBL。

先不做

  • 屏幕空间 SSS blur。
  • thickness shadow map。
  • 多层树冠体积透射。
  • 完整 SpeedTree 官方 shader 还原。
float backLit = pow(max(dot(-N, L), 0.0), u_foliageFactors.y);
float wrapped = max((dot(N, L) + u_foliageFactors.x) / (1.0 + u_foliageFactors.x), 0.0);
vec3 transmission = lightColor * lightIntensity
    * baseColor
    * u_transmissionColor.rgb
    * u_transmissionColor.a
    * backLit
    * wrapped;

风数据导入

SpeedTree 官方资料里需要区分离线缓存风和实时 SDK 风。VulkanLearn 第一版不直接依赖这两条完整路线，而是把 SpeedTree 静态几何转换成自己的 foliage 中间格式。

官方路线

  • Modeler 的 VFX Wind 可以导出 FBX point cache 或 Alembic，更适合影视/VFX 缓存动画。
  • SDK 路线通过 .stsdk / CCore 保存风配置，并由 CWindStateMgr 生成 shader constants。
  • 官方性能文档也把风成本主要归到 vertex shader，并建议按 Full、Branch、Global、None 做风 LOD。

VulkanLearn 第一版

  • 导入静态 FBX/GLB 的 mesh section、material slot 和 vertex stream。
  • 转换到 FoliageVertex.wind0/wind1/wind2。
  • scene/config 提供全局 WindParameters。
  • foliage.vert 与 foliageShadow.vert 共享同一份 wind deformation。
SpeedTree static mesh export
    -> Assimp / converter reads sections, material slots, vertex streams
    -> VulkanLearn FoliageVertex wind0 / wind1 / wind2
    -> model descriptor records wind import policy and optional defaults
    -> scene/config provides global WindParameters
    -> foliage.vert and foliageShadow.vert consume the same wind data
导入优先级 来源 落到 VulkanLearn
1 SpeedTree 导出文件里明确存在的 extra vertex attributes wind0/wind1/wind2
2 额外 UV channel 或 vertex color 中可稳定识别的权重、phase、leaf group branchWeight、leafWeight、phase
3 转换工具根据 mesh section / material slot / leaf card bounds 生成的默认值 primaryPivotOS、stiffness、默认权重
4 model descriptor JSON 中显式写入的 fallback 策略 windImport.defaults

约束：可以在转换阶段生成默认 pivot 和权重，但不要在 shader 每帧根据 position 临时猜 pivot。生成结果要落到模型数据或派生资产里，便于调试和复现。

"windImport": {
  "mode": "Generated",
  "source": "SpeedTreeStaticMesh",
  "useVertexColor": true,
  "useExtraUv": true,
  "generateLeafPivotFromSectionBounds": true,
  "defaults": {
    "branchWeight": 0.5,
    "leafWeight": 1.0,
    "stiffness": 0.2
  }
}

完整 SpeedTree 风

长期目标是支持完整 SpeedTree 游戏风。这里的完整不是解析 FBX point cache，而是读取 SpeedTree Modeler 中调好的 SDK 风配置、顶点风属性和风 LOD 语义，并在 VulkanLearn 的实时 vertex shader 中还原。

先 probe，后定格式：正式设计 VulkanLearn runtime foliage asset 前，先执行 documents/plan/rendering/speedtree-sdk-data-probe.md。第一轮只通过 SDK 枚举 .stsdk 暴露的材质、LOD、draw call、顶点流、风和 billboard 数据，并输出 verbose probe JSON。

完整目标

  • 读取 SpeedTree SDK runtime asset 中的 wind config。
  • 读取或转换 branch level、leaf group、weights、phase、pivot/axis、frond/leaf ripple/tumble。
  • CPU 侧根据 time、strength、direction、gust 生成 SpeedTree 风语义一致的 shader constants。
  • GPU 侧执行 branch / leaf / frond wind deformation。
  • 支持 Full、Branch、Global、None 风 LOD。

边界

  • 推荐走 SDK-backed importer，不逆向未授权的 .stsdk 私有格式。
  • 没有 SDK 时，只能承诺 Generated / Approximate wind backend。
  • FBX point cache / Alembic 仍视为离线缓存，不作为大规模游戏实时风主线。
.stsdk / SpeedTree runtime asset
    -> SM_xxx.json model descriptor
    -> type = "speedtree"
    -> SpeedTreeParserCore or SDK-backed importer
    -> importer exposes geometry, LOD, material, wind config
    -> VulkanLearn converts geometry to MeshSection / FoliageVertex
    -> CWindStateMgr or equivalent wrapper updates wind constants
    -> VulkanLearn uploads SpeedTreeWindParameters
    -> GLSL port of SpeedTree wind shader functions
    -> foliage and foliageShadow passes share the same deformation

资产入口：.stsdk 是 source asset，SM_xxx.json 是 VulkanLearn 的资产入口和验证边界。通过 type: "speedtree" 分派解析；materialSlots 必须是非空有序数组，数量必须与 .stsdk 解析出的 material 数量一致，数组顺序对应 SpeedTree material 顺序，name 仅用于配置可读性和调试，不参与映射。.st9 暂时只作为 UE5.7 对照输入，不作为主解析入口。

UE 5.7 参考结论

本机 UE 5.7 的 SpeedTreeImporter 可作为现代游戏引擎接入参考。插件目录在 D:\sofeware\Epic Games\UE_5.7\Engine\Plugins\Editor\SpeedTreeImporter，风 shader 入口在 Engine\Shaders\Private\SpeedTreeCommon.ush，CPU 风状态在 Engine\Source\Runtime\Engine\Public\SpeedTreeWind.h 与 Engine\Source\Runtime\Engine\Private\SpeedTreeWind.cpp。

导入事实

  • UE5.7 支持 .srt、.st、.st9 导入。
  • v9 导入会创建 UStaticMesh、material instances 和 SpeedTree9 master material 派生实例。
  • SpeedTree draw call / material 会落到 StaticMesh material slots，和 VulkanLearn 的 materialSlots 方向一致。

风数据事实

  • 实时风数据以顶点属性进入 mesh，UE 将 SpeedTree9 branch/ripple 数据打包到 UV 通道。
  • CPU 侧更新风强、风向、gust 和振荡时间，GPU 侧在 vertex shader 做 global、branch、leaf、frond deformation。
  • 这条路线比截 Modeler OpenGL 旧管线更适合作为 VulkanLearn 还原目标。
UE5.7 SpeedTree9 vertex UV layout
UV0: Diffuse UV
UV1: Branch1Pos, Branch1Dir
UV2: Branch1Weight, RippleWeight
UV3: Lightmap UV
UV4: Branch2Pos, Branch2Dir      if Branch2 data exists
UV5: Branch2Weight, unused       if Branch2 data exists
UV6+: camera-facing anchor data  if facing geometry exists

结论：VulkanLearn 不直接照搬 UE 的 UV 号位，但会吸收这些语义，转换为自己命名清楚的 SpeedTreeVertex / FoliageVertex 字段，例如 branch1、branch2、ripple、blend 和 camera-facing anchor。

阶段 任务 验收
SDK 验证 链接 SpeedTree SDK，加载一棵 .stsdk 测试树，枚举 source、material、LOD、draw call、vertex stream、wind、billboard。 能输出 generated/speedtree_probe/*.probe.json，且暂不固定最终 runtime 格式。

LOD 对齐 实现 Full、Branch、Global、None 风 LOD。 风 LOD 切换稳定，主 pass 和 shadow pass 同步。

Wind 与 Pivot

官方文档把风分成全局、branch、leaf、frond、gusting 等层次，并强调风成本主要在 vertex shader。VulkanLearn 的路线也按这个方向做，但先从最便宜的全局/branch 摆动开始，multi-pivot 和 leaf flutter 放到有数据后再做。

层级 第一版做法 后续升级
Global 按高度和风向整体轻微弯曲。 加入 preserve shape 或 bounds padding。
Branch vertex color 或 wind0.x 控制摆动权重。 按 primary pivot 做旋转式 branch sway。
Leaf 先不单独 flutter，或只做小幅 normal/position offset。 按 leaf group、phase、secondary pivot 做 flutter/tumble。
Shadow 与主 pass 共享 foliageWind.glsl。 如果做 wind LOD，shadow pass 使用同一 LOD 选择。

验收清单

第一轮完成标准

  • 场景里有一棵 SpeedTree 来源的多 section 树。
  • material slot 能映射到材质实例。
  • 树干和叶片材质分离。
  • 叶片 alpha cutout 和双面显示稳定。
  • 逆光时有可调 transmission。
  • 风强度调高时树冠会动。
  • 风强度为 0 时完全静止。

风险点

  • Assimp 是否保留 SpeedTree 导出的额外属性。
  • submesh/material slot 前置后，旧单 mesh 资产也要迁移到 materialSlots。
  • shadow pass 需要跟 foliage 主 pass 共用 alpha 和 wind。
  • multi-pivot 没有资产数据时不能可靠实现。
