Deferred 完整 GBuffer 与 Shader 结构升级计划

本文档定义 VulkanLearn 从当前 forward-style PBR 管线升级到 deferred 管线的计划。目标调整为直接完整对齐 Unreal Engine legacy deferred GBuffer 的职责和槽位：geometry/base pass 写出 GBufferA/B/C/D/E、Velocity 与可选 tangent/anisotropy 数据，lighting pass 统一根据 ShadingModelID 和 SelectiveOutputMask 解释这些属性。

当前工程的 geometry pass 已经输出 HDR color 和 depth，pbr.frag 在同一个片元 shader 内完成材质采样、直接光、阴影、IBL 与 debug view。Deferred 升级后，这些职责需要拆成“材质求值”和“光照求值”两个可复用层。

UE 对齐范围

UE 的 deferred 路径核心思想是把 material / object attributes 存入 GBuffer，再由 deferred lighting 基于这些属性计算光照。VulkanLearn 这次直接对齐 legacy deferred 的完整 GBuffer 语义：A/B/C/D/E、Velocity、ShadingModelID、SelectiveOutputMask、CustomData、PrecomputedShadowFactors、可选 world tangent / anisotropy。UE5 Substrate Adaptive GBuffer 是另一套按像素变化的复杂存储系统，不作为本次目标。

UE 风格概念 在 VulkanLearn 中的含义 VulkanLearn 对齐要求
ShadingModelID 每个像素选择 shading 解释方式，例如 DefaultLit、Unlit、ClearCoat。 必须引入完整 ID 空间。先实现 DefaultLit 和 Unlit，但枚举和值域为后续 ClearCoat、Subsurface、Hair、Cloth、Eye 等模型预留。
SelectiveOutputMask 每个像素声明哪些 optional output / custom data 有效。 按 UE 风格与 ShadingModelID 打包到同一通道，低位是 shading model，高位是 per-pixel optional output flags。
CustomData 特殊 shading model 复用的额外参数槽。 必须作为 GBufferD 常驻槽位进入布局，即使早期只有默认值。
PrecomputedShadowFactors 静态光照、烘焙阴影或 lightmap 相关数据。 必须作为 GBufferE 常驻槽位进入布局。当前没有 lightmap 时写默认值，后续静态光照直接接入。
Velocity motion vector，服务 TAA / TSR / motion blur。 必须纳入完整布局。当前无 motion vector 时写零，后续 TAA / motion blur / TSR 类路径直接消费。
WorldTangent / Anisotropy 各向异性 BRDF 的切线方向和强度。 作为可选 GBufferF 或等价 attachment 进入完整布局，由 HAS_ANISOTROPY_MASK 标记有效性。
这里的完整对齐指 legacy deferred GBuffer 的槽位、字段语义、packed mask 语义和 shader 数据流对齐。具体 Vulkan 格式可以先用更易调试的格式，后续再压缩到更接近 UE 的带宽形态。

完整 GBuffer 布局

GBuffer 从第一版开始就按 UE legacy deferred 的完整职责建模。早期没有真实数据的槽位也要写入默认值，避免后续 ClearCoat、SSS、anisotropy、velocity、lightmap 接入时再次迁移 render graph 和 shader binding。

资源名 建议格式 通道语义 UE 对应职责
gbufferA A2B10G10R10_UNORM_PACK32 rgb = encoded world normal, a = PerObjectGBufferData 对齐 UE Legacy 的法线槽位；当前 VulkanLearn 尚未接入 per-object data producer，alpha 写 0。
gbufferB R16G16B16A16_SFLOAT（特殊模型扩展） r = metallic, g = specular, b = roughness, a = packed ShadingModelID + SelectiveOutputMask alpha 按低 4 位 shading model、高 4 位 optional flags 解释并归一化存储；Eye/Hair 的既有扩展字段继续复用 B.rg。
gbufferC R16G16B16A16_SFLOAT（Hair absorption 扩展） rgb = baseColor, a = ambientOcclusion 对齐 UE Legacy 的 BaseColor/AO 槽位；Hair 的 rgb 继续保存线性米制 absorption，因此暂不改为 sRGB/8-bit。
gbufferD R16G16B16A16_SFLOAT rgba = customData 对齐 UE 给 ClearCoat、SSS、Hair、Eye 等 shading model 复用的 custom data。
gbufferE R16G16B16A16_SFLOAT rgba = precomputedShadowFactors 对齐 UE 的静态光照 / 预计算阴影因子槽位。当前无烘焙数据时写默认值。
gbufferVelocity R16G16_SFLOAT 或 R16G16B16A16_SFLOAT rg = screen velocity, 其余通道预留 对齐 UE 的 velocity 输出，服务 TAA、motion blur 和后续重投影类效果。
gbufferF R16G16B16A16_SFLOAT rgb = worldTangent, a = anisotropy 对齐 UE 的各向异性 optional 数据职责，由 HAS_ANISOTROPY_MASK 控制有效性。
sceneColorBase R16G16B16A16_SFLOAT rgb = emissive / base pass scene contribution, a = opacity 或 SSS transmissionWeight 不是 GBuffer 槽位。常规模型保存 opacity；当前 opaque Subsurface 像素复用 alpha 保存 transmission weight。
sceneDepth D32_SFLOAT 深度，用于重建 world position。 deferred lighting 的位置来源。

完整对齐后的渲染流程

shadow
  -> geometry / gbufferGeometry
  -> deferredLighting
  -> sky
  -> bloom
  -> toneMapping

为了减少初次改造冲击，可以先保留 pass 名称 geometry，但改变它的输出语义：从 “final-ish HDR color” 改成 “UE-style GBuffer attributes + sceneColorBase”。新增 deferredLighting 输入完整 GBuffer，输出 sceneColor。后续 sky、bloom、tone mapping 继续围绕 sceneColor 运行；如果以后加入真正的后处理效果，再单独恢复 post-process pass，而不是为了 copy 保留一张 offscreenColor。

阶段 7 当前主流程

shadow
  -> geometry          // 写 GBufferA/B/C/D/E、Velocity、F、sceneColorBase、sceneDepth
  -> deferredLighting  // 读取 GBuffer + sceneDepth + shadowMap，并使用 Set 0 的 IBL 资源
  -> sky
  -> bloom
  -> toneMapping

阶段 7 已经不再用 GBuffer debug pass 代替光照。GBuffer attachment 的检查交给 RenderDoc；工程主链只保留真实渲染职责：deferredLighting 消费同一套 GBuffer、sceneDepth 和 shadowMap，并结合全局 IBL 资源输出 sceneColor。offscreenColor 不再作为固定中间图存在。

SelectiveOutputMask

SelectiveOutputMask 是每像素 feature flags。它不决定物体是否进入 GBuffer，而是告诉后续 pass：这个像素有哪些可选数据有效，哪些输出可以被视为默认值。

字段 建议位置 用途
ShadingModelID packed low bits 选择 BRDF / shading 模型。
SelectiveOutputMask packed high bits 声明 custom data、anisotropy、shadow、velocity 等 optional 数据是否有效。 
// UE-style packed channel：存储到 gbufferB.a。
// 低 4 bit: ShadingModelID
// 高 4 bit: SelectiveOutputMask
// UE 5.8 Legacy Material Shading Model ID；未实现模型仍保留原始槽位。
const uint SHADING_MODEL_UNLIT = 0u;
const uint SHADING_MODEL_DEFAULT_LIT = 1u;
const uint SHADING_MODEL_SUBSURFACE = 2u;
const uint SHADING_MODEL_PREINTEGRATED_SKIN = 3u;
const uint SHADING_MODEL_CLEAR_COAT = 4u;
const uint SHADING_MODEL_SUBSURFACE_PROFILE = 5u;
const uint SHADING_MODEL_TWOSIDED_FOLIAGE = 6u;
const uint SHADING_MODEL_HAIR = 7u;
const uint SHADING_MODEL_CLOTH = 8u;
const uint SHADING_MODEL_EYE = 9u;
const uint SHADING_MODEL_SINGLE_LAYER_WATER = 10u; // reserved
const uint SHADING_MODEL_THIN_TRANSLUCENT = 11u;
const uint SHADING_MODEL_STRATA = 12u; // reserved

const uint GBUFFER_HAS_CUSTOM_DATA_MASK = 0x10u;
const uint GBUFFER_HAS_PRECOMPUTED_SHADOW_MASK = 0x20u;
const uint GBUFFER_HAS_VELOCITY_MASK = 0x40u;
const uint GBUFFER_HAS_ANISOTROPY_MASK = 0x80u;

float EncodeGBufferPacked(uint shadingModel, uint flags)
{
    return float((shadingModel & 0x0fu) | (flags & 0xf0u)) / 255.0;
}

uint DecodeShadingModel(float packedValue)
{
    return uint(packedValue * 255.0 + 0.5) & 0x0fu;
}

uint DecodeGBufferFlags(float packedValue)
{
    return uint(packedValue * 255.0 + 0.5) & 0xf0u;
}
gbufferB.a 按 8-bit packed channel 固定语义，实际 attachment 值使用 packed / 255.0 的归一化表示；decode 先乘回 255，再按低 4 bit / 高 4 bit 解释 UE-style shading model 与 optional flags。

Shader 结构

升级的关键不是多写一个 deferred lighting shader，而是把材质 shader 拆成可复用层。Forward 与 Deferred 应共享同一套材质采样和 surface 语义，只在“输出到哪里”和“何时计算 lighting”上分叉。最终形态应进一步收敛成 UE-like authoring：材质作者只写 VS/PS 的可控入口，其余 binding、GBuffer 编码、lighting 分发和 pass 差异由框架层包起来。

当前问题

  • pbr.frag 同时负责材质采样、normal decode、BRDF、阴影、IBL 和 debug view。
  • 材质参数和 lighting 强绑定，导致 deferred 难以复用。
  • 后续加 ShadingModelID 时，如果仍堆在一个 shader 内，会让 forward/deferred 分叉越来越多。

目标结构

  • 材质采样只生成 MaterialSurface。
  • GBuffer 编码只消费 MaterialSurface。
  • Forward 直接把 MaterialSurface 交给 lighting。
  • Deferred 先写 GBuffer，再由 lighting pass 解码成 MaterialSurface。

推荐 include 分层

文件 职责 被谁使用

结构关系总览

pbr.vert
  vertex attributes + common UBO
    -> Fill MaterialVertexContext
    -> MaterialVertex(inout vertex)        // 作者可见的顶点入口
    -> MaterialVertexOutput
    -> MaterialVaryings v2f                // 明确的 vertex-to-fragment 边界

pbr.frag

    -> CreateMaterialPixelContext(v2f)     // 必须接收完整 v2f，避免丢失切线/颜色等阶段数据
    -> CreateDefaultMaterialSurface()
    -> MaterialPixel(pixel, surface)       // 作者可见的片元入口

void main()
{
    MaterialPixelContext pixel = CreateMaterialPixelContext(v2f);
    MaterialSurface surface = CreateDefaultMaterialSurface();
    MaterialPixel(pixel, surface);

    #if VL_MATERIAL_OUTPUT_GBUFFER
        GBufferData gbuffer = BuildMaterialGBufferOutput(surface, pixel);
        WriteGBuffer(gbuffer);
    #else
        outSceneColor = BuildMaterialForwardOutput(surface);
    #endif

这里的 v2f 只是 vertex-to-fragment 的命名，不表示项目切到 DX 或 OpenGL。VulkanLearn 当前 shader 源是 Vulkan GLSL，编译到 SPIR-V；MaterialVaryings 只负责把阶段边界结构化，不改变项目现有的 Vulkan 坐标和 layout 约定。

MaterialVertex / MaterialPixel 输入输出

入口 输入 输出 不负责
MaterialVertex(inout MaterialVertexContext vertex) modelMatrix、localPosition、localNormal、localTangent、texCoord、vertexColor。 clipPosition 写给 gl_Position；worldPosition、worldNormal、worldTangent、texCoord、vertexColor 写入 MaterialVaryings。 不做 lighting、GBuffer 编码、debug view，也不直接绑定 descriptor。
MaterialPixel(in MaterialPixelContext pixel, inout MaterialSurface surface) 从完整 MaterialVaryings 展开的 worldPosition、worldNormal、worldTangent、texCoord、vertexColor。 填充 MaterialSurface：base color、opacity、normal、roughness、metallic、AO、emissiveColor、shading model 和 custom data。 不决定 forward/deferred，不写 render target，不处理 shadow、IBL 和 post-process。

    vec3 worldPosition;
    vec3 worldNormal;
    vec4 worldTangent;
    vec3 baseColor;

Forward 与 Deferred 的共用关系

// pbr.frag：同一套材质函数，编译期按 render mode 选择输出壳。
void PbrFragment()
{
    MaterialPixelContext pixel = CreateMaterialPixelContext(v2f);
    MaterialSurface surface = CreateDefaultMaterialSurface();
    MaterialPixel(pixel, surface);

    #if VL_MATERIAL_OUTPUT_GBUFFER
        GBufferData gbuffer = BuildMaterialGBufferOutput(surface, pixel);
        WriteGBuffer(gbuffer);
    #else
        outSceneColor = BuildMaterialForwardOutput(surface);
    #endif
}

// deferred lighting fragment
void DeferredLightingFragment()
{
    MaterialSurface surface = ReadGBuffer(uv, sceneDepth);
    vec3 color = ShadeDeferredSurface(surface, lightingContext);
    outColor = vec4(color, surface.opacity);
}
这样写完以后，forward 不是被废弃，而是变成 deferred 的自然补充：透明物体、特殊调试、简单平台 fallback、后续 editor gizmo 都可以继续走 forward。

UE-like Authoring Facade

是的，deferred 升级应该同时抽离出一个材质 shader 编写外壳。材质作者不应直接关心 Vulkan descriptor set、GBuffer attachment layout、forward/deferred 分叉、lighting pass、debug view 或 velocity/precomputed shadow 的默认值。对作者暴露的应该是少量稳定入口，类似 UE 材质最终只是在引擎提供的模板里填充材质表达式。

当前工程里，pbr.vert + pbr.frag 这样的 shader pair 天然就是材质定义。为了让编译/装配有稳定起点，本计划正式引入 M_*.json 作为材质定义资产：它包含 name、shadingModel、renderStates、parameters、数字值 macros、textures。M_*.json 不重复写 shader 字段，而是按命名约定绑定 shader pair，例如 M_pbr.json -> pbr.vert / pbr.frag。macros 在 M_*.json 中声明可调 static/material macros 和默认值，MI_*.json 可以用同名数字宏覆盖它们；这类 override 会参与 shader variant key，类似 UE Material Instance 的 static switch。renderStates 主归属在材质定义层，MI_*.json 不再直接写完整 renderStates，只允许通过 renderStateOverrides 做 UE Base Property Override 风格的显式覆写；这里的命名保留为 renderStateOverrides，但语义包含材质静态属性覆盖，不只等同于 Vulkan pipeline state。shadingModel 默认来自 M_*.json，也允许被 MI_*.json -> renderStateOverrides.shadingModel 覆盖；它不是普通 uniform，而是参与 EffectiveMaterial 合成、shader variant key、pipeline key 和 GBuffer ShadingModelID 写入的静态材质属性。textures 保留贴图槽的 type 和默认值，其中 type 的主要职责是校验 default 或 MI_*.json override 指向的 texture JSON 是否合规；生成 sampler 声明只是派生用途。binding 和 macro 不在每个 texture 上重复写，由生成规则统一决定。M_*.json 会生成一份 Paramter include 文件，默认路径是同目录下的 generate/<name>Paramter.glsl。对应的 vert 和 frag 需要事先 include 这个文件，再使用其中生成的宏、参数声明、贴图声明和材质常量。MI_*.json 只引用 M_*.json 并提供参数、贴图、static macro override 和可选 render state override。代码里的 Material 类仍更接近运行时 pipeline / shader variant 缓存载体，不等同于磁盘上的 M_*.json。

作者可见

  • 顶点阶段入口：修改局部顶点、法线、切线、UV、vertex color、world position offset。
  • 片元阶段入口：填充 MaterialSurface，包括 baseColor、roughness、metallic、normal、emissiveColor、customData、shadingModel。
  • 材质模块 public 接口：例如 normal map、clear coat、foliage SSS、wind、dissolve。
  • 材质参数声明：仍由反射系统负责真实 binding。

框架隐藏

  • Descriptor set / binding 位置和 pass descriptor 对齐。
  • GBufferA/B/C/D/E、Velocity、F 的写入位置和默认值。
  • Forward 与 Deferred 的输出分流。
  • ShadingModelID / SelectiveOutputMask 的 packing。
  • Lighting、shadow、IBL、debug view、post-process 输入约定。

// generated/assembled forward fragment
void ForwardPbrFragment()
{
    MaterialPixelContext pixel = CreateMaterialPixelContext(v2f);
    MaterialSurface surface = CreateDefaultMaterialSurface();
    MaterialPixel(pixel, surface);
    ForwardLightingResult lighting = ShadeForwardSurfaceDetailed(surface);
    vec4 finalColor = vec4(lighting.finalColor, surface.opacity);
    MaterialDebugLightingData debugLighting = CreateMaterialDebugLightingData(
        lighting.shadow,
        lighting.directLighting,
        lighting.indirectDiffuse,
        lighting.indirectSpecular);
    outColor = ResolveMaterialDebugView(surface, debugLighting, finalColor);
}

// generated/assembled deferred gbuffer fragment
void DeferredGBufferFragment()
{
    MaterialPixelContext pixel = CreateMaterialPixelContext(v2f);
    MaterialSurface surface = CreateDefaultMaterialSurface();
    MaterialPixel(pixel, surface);
    WriteCompleteGBuffer(surface);
    outSceneColorBase = vec4(surface.emissiveColor, surface.opacity);
}
Debug view / ENABLE_DEBUG_VIEW 这一套也归到 engine 层：材质作者只填 MaterialSurface，forward 和 deferred 分别把自己的 lighting result 转成 MaterialDebugLightingData，最终颜色统一走 ResolveMaterialDebugView。当前封装在启用 debug view 时用 mask/mix 选择显示项，release 或未启用宏时直接返回默认颜色，避免把动态分支散落到每个材质函数里。

材质定义资产 M_*.json 编译/装配起点。声明 name、shadingModel、parameters、数字值 macros、textures，并默认生成 generate/<name>Paramter.glsl。
材质实例资产 MI_*.json 只引用 M_*.json 并 override static macros、参数、贴图和可选 renderStateOverrides；shadingModel 若需要实例级变化，只能放在 renderStateOverrides.shadingModel，并按静态材质属性处理。

可选材质模板 templates/forward.frag.glsl、templates/gbuffer.frag.glsl 当需要同一材质定义生成 forward / gbuffer 两套最终 shader 时引入。第一阶段先生成 Paramter include，不强制引入完整模板装配器。

engine 材质框架 shader/glsl/engine/*.glsl 提供 MaterialVertexContext、MaterialVaryings、MaterialPixelContext、MaterialSurface、forward/deferred lighting、debug view 和 GBuffer codec。
materialFunction 材质函数 shader/glsl/materialFunction/*.glsl 提供具体材质模块，例如 EvaluatePbrSurface。这里可以读取 M_*.json 生成的参数、贴图和 static macros。

运行时 Material C++ cache object 保留为 pipeline / shader variant 缓存载体，不在第一阶段提升为独立 authoring 资产。
这个外壳应该和现有材质模块文档保持一致：模块提供 public 函数和参数，shader pair 内的作者入口显式调用模块。第一阶段可以不引入生成器；后续如果加入模板装配，生成器也只负责 include、宏变体和模板拼接，不自动猜测材质逻辑顺序。这样既像 UE 一样隐藏引擎细节，又保留当前项目学习时需要的可读性。

UE 对齐审查

这一轮审查的结论是：VulkanLearn 不需要复制 UE 的资产格式，但职责边界要对齐 UE。M_*.json 对应材质定义，MI_*.json 对应材质实例；shader pair 是材质代码，运行时 Material 只是 pipeline / variant 缓存对象。

UE 概念 VulkanLearn 对应 审查结论
Material M_*.json + shader pair 负责 shadingModel、render states、可调 static macros、参数/贴图槽声明和默认值。
Material Instance MI_*.json 只 override 参数、贴图、M_ 暴露的 static macros，以及显式 renderStateOverrides；不选择 shader pair。shadingModel 可以通过 renderStateOverrides.shadingModel 覆盖，但它会进入变体/管线选择，而不是作为普通参数上传。
Static Switch / Static Parameter MI_*.json -> macros 允许实例调节，参与 shader variant key。它不是普通 runtime uniform。
Scalar / Vector / Texture Parameter MI_*.json -> parameters/textures 运行时实例数据，按 M_ 声明和 shader reflection 校验。
Blend Mode / Cull Mode M_*.json -> renderStates 默认归属材质定义层。实例级变化使用 MI_*.json -> renderStateOverrides 显式覆盖，并参与 EffectiveMaterial / pipeline key。
Shading Model Override MI_*.json -> renderStateOverrides.shadingModel 对齐 UE Material Instance Base Property Override。它改变 GBuffer ShadingModelID 和 lighting dispatch，必须参与 shader variant key / pipeline key，不进入 material parameter UBO。

Render Graph 改造点

RenderGraph 需要一次性承载完整 UE-style GBuffer attachment，并允许后续 pass 把这些 attachment 作为 sampled texture 输入。当前配置系统已经能声明多个输出资源，因此重点在资源格式、pass descriptor、shader 绑定、layout transition 和 RenderSystem 分支上。

Descriptor Set 分工保持稳定：Set 0 放全局数据，Set 1 放材质数据，Set 2 放对象数据，Set 3 专门放当前 pass 的 RenderGraph 输入。公共 include 不直接声明 Set 3 资源；具体 pass shader 按自己的 input 顺序声明 binding，避免 shadowMap、GBuffer、post-process 输入互相抢 binding。
层 改造内容 注意点
config/renderGraphConfig.json 新增 gbufferA/B/C/D/E、gbufferVelocity、gbufferF、sceneColorBase，并接入 deferredLighting pass。 后处理链继续消费 sceneColor。GBuffer attachment 命名、shader location 和 deferredLighting.input binding 顺序必须固定。
renderGraph.cpp 确认多 color attachment + depth attachment 顺序稳定，并支持 GBuffer 作为后续 sampled inputs。MSAA 策略也在这里落地。 GBuffer 输出顺序必须与 shader layout(location) 固定对应，文档、JSON、shader codec 三处同步。MSAA 由 RenderGraph 配置显式决定。
sceneLoader.cpp 先读取 MI_*.json 指向的 M_*.json，合并材质定义默认值与实例 override，再按 shader 反射结果解析参数、贴图和 UBO 字段。 shadingModel 默认来自 M_*.json，可由 renderStateOverrides.shadingModel 显式覆盖；默认不作为 material uniform 上传。
shader build step 以 M_*.json 为编译入口，读取 name、shadingModel、parameters、macros 和 textures，生成同目录 generate/<name>Paramter.glsl，再编译 include 该文件的 vert/frag。 最终参与反射的仍是真实 GLSL。MI_*.json 不选择 shader pair，但它的 static macro override 与 shadingModel override 都会选择或触发对应 shader variant。
renderSystem.cpp 保留 geometry draw 分支；deferredLighting、sky、bloom、toneMapping 继续走 fullscreen pass 分支。 先别重写整个 pass dispatch 架构。GBuffer inspection 使用 RenderDoc 直接看 attachment。
source/passBarrier.* 集中处理 pass 边界上的 Vulkan image layout / visibility transition。 不要塞进 commonFunction.h。它只根据 RenderGraph 的 inputResources、outputResources 和 outputLoadOps 推导是否需要 barrier。

PassBarrier 规划

PassBarrier 是 RenderGraph 和 Vulkan 同步之间的薄封装。RenderSystem 不再在主渲染循环里展开一大段 barrier 判断，也不使用临时 lambda；它只在每个 pass 的 beginRenderPass 前调用 PrepareForPass，让资源等待和 layout 转换由 pass 的输入/输出声明自动推导。 

for each pass:
    PassBarrier::PrepareForPass(commandBuffer, renderGraph, passIndex, swapChainImageIndex)
    beginRenderPass()
    draw pass
    endRenderPass()
  • 当前 pass 的 inputResources：如果上一用途是 attachment，就在 pass 前转到 shader-read layout。
  • 当前 pass 的 outputResources：如果 loadOp=load 且上一用途是 sampled input，就在 pass 前转回 attachment layout。
  • storeOp 决定 pass 结束时是否保存 attachment 内容；是否需要等待/转换则主要由后续 input/output 用途决定。
  • 这里转换的是 Vulkan image layout，不是 R16G16B16A16_SFLOAT、D32_SFLOAT 这类像素 format。
  • 典型链路：geometry 写 sceneDepth，deferredLighting 采样 sceneDepth，sky 再以 loadOp=load 继续用它做深度测试。

MSAA 策略

MSAA 在 deferred 管线里不是没用，而是不能再像 forward 那样简单理解为“geometry pass 开 MSAA 然后 resolve color”。Deferred 的 geometry pass 写的是材质属性，不是最终颜色；如果直接硬件 resolve GBuffer，就会把 normal、roughness、metallic、shading model、custom data 这些离散或非线性属性混在一起，边缘像素会得到物理上不成立的材质数据。

方案 优点 问题 VulkanLearn 取向
GBuffer 不开 MSAA，后续走 TAA / FXAA / SMAA 实现最清晰，GBuffer 采样和 lighting 简单，符合现代 deferred 常见路线。 几何边缘需要依赖后处理抗锯齿和 temporal 稳定性。 推荐默认值。不是强制规则，专业配置可按目标质量和成本开启其他路线。
MSAA GBuffer + per-sample deferred lighting 几何边缘质量最好，理论上最接近 forward MSAA。 带宽、显存和 lighting 成本都成倍上升，shader 和 descriptor 复杂度明显增加。 作为高级实验，不进入第一轮落地。
MSAA GBuffer + custom resolve 可以针对 normal、depth、shading model 等属性写专门 resolve 规则。 每类属性 resolve 规则不同，尤其 shading model/custom data 不能线性平均。 后续需要边缘质量时再做。
只对 forward transparent / special pass 开 MSAA 透明物体、线框、编辑器辅助物等仍可得到 MSAA 收益。 需要混合 deferred scene color 与 forward pass 的 sample 策略。 推荐保留。Deferred opaque 不开 MSAA，forward 补充 pass 可按需开。
因此本文档不把 MSAA 写成强制规则。RenderGraph 应暴露清楚的 pass/resource 配置，让专业配置者决定当前 pass 是否开启 MSAA，以及使用普通 resolve、custom resolve 还是 per-sample lighting。项目默认建议 opaque deferred GBuffer 使用 single-sample，forward transparent、debug line、editor gizmo 或其他 special pass 可以继续通过 pass 级配置开启 MSAA。

实施阶段

阶段 1：引入 M_ 材质定义资产

  • 新增 M_*.json 格式，作为 shader 编译/装配入口，字段包括 name、shadingModel、renderStates、parameters、数字值 macros、textures 和兼容 pass；shader pair 由命名约定推导，例如 M_pbr.json -> pbr.vert / pbr.frag。
  • 由 M_*.json 生成同目录 generate/<name>Paramter.glsl，其中包含材质宏、shading model 常量、参数 UBO 声明和贴图声明。
  • 对应的 vert 和 frag 必须先 include 该 gen，再编写 MaterialVertex / MaterialPixel 逻辑。
  • 调整 MI_*.json：不再直接声明 shader 选择、完整 render state 或旧宏列表，改为引用 material: "materials/M_xxx.json"，并只保留参数、贴图、static macro override 和可选 renderStateOverrides。其中 renderStateOverrides 是 UE Base Property Override 风格的显式覆盖，可包含 shadingModel、twoSided、blendMode 等静态材质属性。
  • 加载时先合并 M_*.json 默认值和 MI_*.json override，再交给现有反射校验。

阶段 2：引入 ShadingModel shader 声明

  • 在 shadingModel.glsl 中定义 UE-style ShadingModelID 枚举值域：至少预留 DefaultLit、Unlit、Subsurface、PreintegratedSkin、ClearCoat、SubsurfaceProfile、TwoSidedFoliage、Hair、Cloth、Eye。
  • M_*.json 声明材质定义的默认 shadingModel，当前材质 shader pair 或后续模板中写入一致的 surface.shadingModel。
  • MI_*.json 不增加顶层 shadingModel 字段；如需实例级覆盖，使用 renderStateOverrides.shadingModel。shader 装配步骤可导出材质元数据供 C++ 校验和 debug 使用，但默认不把 shadingModel 作为 material uniform 传入。
  • 保持当前 forward 输出不变，先验证数据链路。

阶段 3：拆 shader 公共结构

  • 从 pbr.frag 拆出 common/shadingModel.glsl、engine/materialSurface.glsl、engine/forwardLighting.glsl、engine/materialDebugView.glsl 和 materialFunction/mf_pbrSurface.glsl。
  • 让现有 forward PBR 改用 MaterialPixel -> EvaluatePbrSurface -> ShadeForwardSurfaceDetailed，debug view 通过 ResolveMaterialDebugView 封装。
  • common/ 只保留通用基础设施，具体 PBR 参数、贴图和 static macros 留在 materialFunction/。
  • 确认输出画面与拆分前一致。

阶段 4：在现有 shader pair 内建立材质入口

  • 定义 MaterialVertexContext、MaterialVaryings、MaterialPixelContext、MaterialSurface 的稳定 public 字段。
  • MaterialVaryings 作为 v2f 结构体从 vertex stage 传到 fragment stage；CreateMaterialPixelContext 必须接收完整 v2f，再统一展开 world position、normal、tangent、uv、vertex color。
  • 先在现有 pbr.vert / pbr.frag 内部引入 MaterialVertex 和 MaterialPixel，但保留原有 shader 文件作为真实编译单元。
  • 确认 MI_*.json 通过 M_*.json 间接选择这对 shader，参数和贴图仍由反射校验；若存在 renderStateOverrides.shadingModel，它只影响 EffectiveMaterial、variant key、pipeline key 和 GBuffer ShadingModelID。
  • 后续再按需要新增 forward / gbuffer 模板；模板系统不是第一刀的前置条件。

阶段 5：写 GBuffer pass

  • 新增完整 GBuffer resources：A/B/C/D/E、Velocity、F、sceneColorBase、sceneDepth。
  • 把 geometry pass 输出改成 8 个 color render targets + depth，默认 needMsaa: false，避免直接硬件 resolve 材质属性。
  • 新增 gbufferCodec.glsl，稳定完整 layout location、packed fields 和默认值。
  • GBuffer 可视化检查交给 RenderDoc，工程主链不额外保留 GBuffer debug pass。
  • Pipeline 创建需要知道当前 render pass 的 color attachment 数量，MRT pass 不能继续只创建 1 个 color blend attachment。

阶段 6：接入 deferredLighting

  • 新增 fullscreen deferredLighting.frag。
  • 读取完整 GBuffer + depth，重建 world position。
  • 复用同一套 MaterialSurface 语义和 BRDF/lighting 基础函数，新增 deferred 路径的 ShadeDeferredSurface 或等价 dispatch，让 forward/deferred 的入口命名保持清晰。
  • Unlit 直接输出 baseColor + sceneColorBase/emissiveColor。

阶段 7：恢复现有效果

  • 阴影接入 deferred lighting。
  • IBL 接入 deferred lighting。
  • shadowMap 作为 deferredLighting 的 Set 3 binding 9 输入；GBuffer + depth 继续固定占用 binding 0..8。
  • IBL 继续走 Set 0 全局资源：prefilteredEnvironmentCube 与 brdfLut。
  • 新增 PassBarrier::PrepareForPass，在 pass 开始前按 input/output 自动处理 attachment 与 sampled input 之间的 layout transition。
  • sky / bloom / toneMapping 链路保持可用；post-process 只在有真实效果时作为可选 pass 接回。
  • debug console 中的 tone mapping、bloom 调参继续有效。

阶段 8：启用 UE-style optional 数据

  • gbufferD 已经常驻，此阶段开始让 ClearCoat 或 Subsurface 真正写入 custom data。
  • gbufferVelocity 已经常驻，此阶段开始接入 previous frame matrix 和 motion vector。
  • gbufferE 已经常驻，此阶段开始接入 lightmap / baked shadow / precomputed shadow factors。
  • gbufferF 已经常驻，此阶段开始接入 anisotropy 和 world tangent。
  • gbufferB.a 的 high nibble 正式写入 GBUFFER_HAS_CUSTOM_DATA_MASK、GBUFFER_HAS_PRECOMPUTED_SHADOW_MASK、GBUFFER_HAS_VELOCITY_MASK、GBUFFER_HAS_ANISOTROPY_MASK。
  • GBuffer 保留 optional 数据槽位，但材质 authoring 只暴露已有真实生产者和光照消费路径的输入；Clear Coat 由 shading-model wrapper 固定写入 CustomData，PrecomputedShadowFactors 与 Anisotropy 在对应运行时数据和 BRDF 接入前不提供 MI 开关。

阶段 9：拆出 forward transparent shader 输出壳

  • pbr.frag 不再固定写 GBuffer，而是通过 materialPass.glsl 根据 RENDER_MODE_* 宏做编译期分流。
  • Opaque / OpaqueClip 变体 include materialGBufferOutput.glsl，继续写 GBufferA/B/C/D/E、Velocity、F 和 sceneColorBase。
  • TransparentAlphaBlend / TransparentAdditive 变体 include materialForwardOutput.glsl，直接调用 forward lighting，输出单一 sceneColor，供后续 forwardTransparent pass blend。
  • forward transparent 的 shadowMap 是当前 pass 输入，约定由该 forward 变体声明为 Set 3 binding 0；它不占用 deferredLighting 的 GBuffer 输入绑定。

风险边界

  • MSAA：MSAA 对 deferred 不是没用，也不是引擎强制关闭项。RenderGraph 应允许专业配置者开启，但需要同时声明 resolve / per-sample lighting 策略，避免隐式硬件 resolve 混坏 GBuffer 属性。
  • 透明物体：不进入 deferred GBuffer。保留 forward transparent pass。
  • 材质变体：不要让每个 shading model 都复制一套完整 shader。优先通过共享 surface / lighting 函数组织。
  • Authoring facade：只隐藏引擎模板和 binding 细节，不自动决定材质模块调用顺序；作者入口仍显式组织材质逻辑。
  • 格式压缩：槽位和 bit 语义必须完整对齐；具体 Vulkan format 可以先保持高精度调试格式，再逐步压缩。
  • UE 对齐：本计划对齐 legacy deferred GBuffer。Substrate Adaptive GBuffer 不进入这轮范围，避免把材质系统和 GBuffer 存储系统同时推倒。
