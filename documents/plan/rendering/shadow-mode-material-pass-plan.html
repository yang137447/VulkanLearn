Shadow Mode 与材质 Pass 方案

已废弃： 当前实现不再使用独立 shadowMode。Common ShadowCaster 直接由 renderMode 选择：Opaque 使用公共 Opaque，OpaqueClip 使用公共 Masked，Transparent 跳过 common shadow draw。本文仅保留为历史设计上下文； 当前契约见 documents/rendering/csm-shadow-map-m1.md。

本方案把 shadow 投影策略变成材质的显式静态属性：M_*.json 必须声明 shadowMode，MI_*.json 可通过 renderStateOverrides 覆写。 不做 Default 推导，避免材质作者和引擎运行时对投影行为产生隐式分歧。

目标

  • 让 opaque、masked、transparent 材质的投影策略由数据显式表达。
  • 纯 opaque 继续复用公共 M_shadow，减少不必要的 shader variant。
  • masked 材质走材质自己的 shadow variant，复用 albedo alpha、cutoff 和后续 vertex deformation。
  • 半透材质默认不投普通 shadow，但可以由 MI_ 明确覆写成 Opaque 或 Masked 投影。
  • 保留学习项目的可读性：先用小改动打通 PBR alpha cutout shadow，再扩展到更多 pass role。
核心原则： renderMode 描述主渲染路径，shadowMode 描述投影路径。两者可以相关，但不互相自动推导。

数据契约

M_*.json 必填

材质定义文件是静态材质契约的源头。所有 M_*.json 的 renderStates 必须显式包含 shadowMode。 

{
    "name": "M_pbr",
    "type": "material",
    "shadingModel": "DefaultLit",
    "renderStates": {
        "renderMode": "Opaque",
        "cullMode": "Back",
        "shadowMode": "Opaque"
    }
}

MI_*.json 可覆写

材质实例只在确实需要改变投影行为时覆写 shadowMode。覆写位置沿用现有 renderStateOverrides，和 renderMode、cullMode 保持同一层级。 

{
    "type": "materialInstance",
    "material": "shader/glsl/M_pbr.json",
    "renderStateOverrides": {
        "renderMode": "OpaqueClip",
        "cullMode": "None",
        "shadowMode": "Masked"
    },
    "macros": {
        "USE_ALBEDO_MAP": 1
    },
    "parameters": {
        "u_alphaClipThreshold": 0.45
    }
}
禁止隐式默认： 缺少 shadowMode 的 M_*.json 应在材质定义校验阶段报错。缺少 renderStateOverrides.shadowMode 的 MI_*.json 表示继承 M_，不是运行时推导。

Shadow Mode 语义

值 含义 绘制路径 典型用途
None 不参与 shadow pass，不产生普通 shadow map 投影。 shadow pass 跳过 draw。 透明特效、additive、火焰、纯屏幕表现物。
Opaque 作为实心物体投影，不评估材质 alpha。 优先复用公共 M_shadow。 普通不透明 mesh、当前无 WPO 的硬表面。
Masked 投影时评估当前材质 alpha clip，只有通过 clip 的像素写深度。 使用当前材质的 shadow variant。 树叶、栅栏、草、cutout decal 类几何。

当前阶段不设计 Translucent shadow。半透投影属于 colored shadow、deep shadow、 ray traced shadow 或体积阴影问题，不应混进普通 shadow map 的第一版。

Shader Variant

增加 shadow variant 时，推荐把 pass role 纳入 ShaderVariantKey。第一阶段可以只支持 Surface 和 Shadow 两类。 

enum class MaterialPassRole
{
    Surface,
    Shadow
};

enum class ShadowMode
{
    None,
    Opaque,
    Masked
};

variant key 建议包含：

  • shaderName：例如 pbr。
  • passRole：例如 Surface 或 Shadow。
  • renderMode：主渲染静态模式，仍参与 surface variant。
  • shadowMode：只对 shadow role 有意义；None 不编译 shadow variant。
  • shadingModelMacro 和材质宏：沿用当前排序归一化规则。

宏输出

// Surface variant
#define RENDER_PASS_SURFACE 1
#define RENDER_MODE_OPAQUE_CLIP 1

// Shadow masked variant
#define RENDER_PASS_SHADOW 1
#define SHADOW_MODE_MASKED 1
变体控制： Opaque 走公共 shadow 材质时不生成材质 shadow variant。只有 Masked 或未来声明需要材质顶点变形的 opaque 才生成 shadow variant。

Shader 结构

材质作者继续维护一份 surface 函数；pass 输出壳负责决定写 GBuffer、forward color，还是 shadow depth。 alpha clip 应从 “只绑定 RENDER_MODE_OPAQUE_CLIP” 调整为可被 shadow masked 复用。 

MaterialSurface EvaluatePbrSurface(in MaterialPixelContext pixel)
{
    MaterialSurface surface = CreateDefaultMaterialSurface();
    vec4 baseColor = SampleOrFallbackBaseColor(pixel);
    surface.baseColor = baseColor.rgb;
    surface.opacity = baseColor.a;
    return surface;
}

void ApplyPbrAlphaClip(in MaterialSurface surface)
{
#if defined(RENDER_MODE_OPAQUE_CLIP) || defined(SHADOW_MODE_MASKED)
    if (surface.opacity < u_alphaClipThreshold)
    {
        discard;
    }
#endif
}

Surface 输出壳

MaterialSurface surface = EvaluatePbrSurface(pixel);
ApplyPbrAlphaClip(surface);

#if VL_MATERIAL_OUTPUT_GBUFFER
    WriteGBuffer(surface, pixel);
#else
    WriteForward(surface);
#endif

Shadow 输出壳

MaterialSurface surface = EvaluatePbrSurface(pixel);

#if defined(SHADOW_MODE_MASKED)
    ApplyPbrAlphaClip(surface);
#endif

// 不写颜色。depth 写入由 render pass 的 depth attachment 完成。

后续接入 wind / WPO 时，shadow vertex variant 必须复用同一份顶点变形函数。否则主视图和阴影轮廓会错位。

Runtime 调度

None跳过

对象仍可参与主渲染，但 shadow pass 不提交 draw，不分配材质 shadow descriptor。

Opaque公共材质

绑定全局 M_shadow pipeline 和对象 UBO，只写深度。适合当前大多数不透明对象。

Masked材质变体

按材质实例加载 shadow variant，绑定 material set 和 object set，采样 alpha 后写深度。

Future材质顶点变形

如果 opaque 材质声明需要 WPO / wind，可升级为材质 shadow variant，即使 shadowMode=Opaque。

Shadow pass 伪代码

for materialGroup in resolvedScene.materialGroups:
    for materialInstanceGroup in materialGroup.materialInstances:
        shadowMode = materialInstanceGroup.materialInstance.GetShadowMode()

        if shadowMode == None:
            continue

        if shadowMode == Opaque and !NeedsMaterialShadowVariant(materialInstance):
            BindCommonShadowPipeline()
            BindGlobalAndObjectSets()
        else:
            BindMaterialShadowPipeline(materialInstance)
            BindGlobalObjectAndMaterialSets()

        DrawObjects(materialInstanceGroup.draws)

落地步骤

  1. 扩展 material schema：M_*.json renderStates.shadowMode 必填，MI_*.json renderStateOverrides.shadowMode 可选。
  2. 扩展 MaterialInstanceResolver：从 M_ 继承 shadowMode，再应用 MI_ 覆写。
  3. 扩展 MaterialInstanceValidator：解析 ShadowMode，把它写入 build plan / material instance。
  4. 保留公共 M_shadow 给 Opaque 使用。
  5. 为 Masked 增加 shadow role variant，并让 PBR shadow fragment 复用 albedo alpha 与 u_alphaClipThreshold。
  6. 改造 DrawShadowScene：按 material instance 的 shadowMode 选择 skip、公共 shadow pipeline 或材质 shadow pipeline。
  7. 给 SpeedTree 叶片创建独立 MI_：renderMode=OpaqueClip、cullMode=None、shadowMode=Masked。

验收

  • Opaque：普通 mesh 仍使用公共 shadow pipeline，阴影行为不退化。
  • None：透明/additive 材质不再产生实心 shadow。
  • Masked：叶片主视图和 shadow map 使用同一 alpha cutoff，阴影轮廓有洞。
  • MI 覆写：同一个 M_pbr 可以由不同 MI_ 配出不投影、实心投影或 masked 投影。
  • 错误暴露：缺少 M_ renderStates.shadowMode 的材质定义在加载阶段报错。

风险

风险 处理
Shadow descriptor 复杂度上升 第一阶段只让 Masked 材质绑定 material set；Opaque 继续使用 object/global set。
variant key 膨胀 None 不生成 shadow variant，Opaque 默认公共 pipeline，只有必要材质进入 shadow variant 缓存。
主 pass 与 shadow pass clip 逻辑分裂 把 alpha clip 抽成材质函数内的共享 helper，禁止在 shadow fragment 复制一套阈值解释。
未来 WPO 阴影错位 在材质定义中增加 “需要材质 shadow vertex” 的显式能力位，或由 vertex deformation 宏触发材质 shadow variant。
