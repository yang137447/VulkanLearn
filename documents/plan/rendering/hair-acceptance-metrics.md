# 头发验收指标筛查（2026-11-23）

状态：计划/决策记录，**不是 runtime 契约**，也不重判任何已冻结的历史结果。
本文只决定“今后哪些数字可以判 FAIL、哪些只记录”，历史 raw 与结论按原身份保留。

## 为什么要筛查

旧行为带 `Ddyn ∈ [.02, .08] L` 把两件不同的事塞进同一条硬门槛：

- 下界 `.02L` 是“+20 m/s² 工程探针下位移要够大”的**筛选尺**。24 项长程里有 **15 项仅因
  Ddyn 低于该下界**被判 FAIL（示例：584 号 N32 `Ddyn=.01496406375L`，4006 号 N32
  `=.02117019532L`），而同一批的静止资格、Dmax、Trec、Rtail、stretch 全部通过。
  位移小可能正是模型更硬、更稳的结果，不是缺陷。
- 上界 `.08L` 是推导渐进支撑 `k2` 用的**单节点、横向、静态额定尺**。
  [最终 CPU 记录](../../rationale/hair-rod-final-cpu-20261120.md) 已明确写它
  “不是所有耦合段动态峰值的上界定理”，但工具仍把它当动态 FAIL 判据；
  八根真实 groom 因此有六根被它判 FAIL。

同类问题还有：`Trec ≤ .5 s` 没有登记为产品目标、240 vs 3840 Hz 的 `.015L` 没有严格误差界、
GPU 性能“未达标”却没有登记预算数字。结果是物理正确性（残差/功账/拉伸/回正）本来有可信
硬门槛，行为层却先被几个不成立的数字挡死。

## 分类

| 类 | 含义 | 后果 |
| --- | --- | --- |
| **G** 硬门槛 | 模型正确性或不变量，失败必须修 | 自动 FAIL，阻止放行 |
| **T** 产品目标 | 观感/性能取舍，需登记依据后人工复核 | 记录并显式标注，不自动 FAIL |
| **D** 诊断 | 只记录数值与上下文 | 不产生 PASS/FAIL |

## 新的硬门槛组合

```
PASS = settled && Dmax<=.015 && Rtail<=.005 && stretch<=.01
```

其余指标（Ddyn、Trec、像素位移、时间误差、GPU 时间）一律记录并进入报告，不再自动判 FAIL。
有限性由 `distance`/`stretch` 传播：出现 NaN/Inf 时 `Rtail` 或 `stretch` 必然失败，
不需要额外的 per-frame clamp 或全局 finite 断言。

## 工具改动与身份

- `tool/hair/rodGroomValidation.cpp` 的 `behavior.csv` 列保持不变（`Ddyn`/`Trec` 继续是诊断列），
  只改 `status` 的计算；长程 `summary.json` 增加 `metricPolicy` 字段，并分别统计目标未达次数
  `behaviorTargetRecoveryMisses` / `behaviorDynamicBandMisses`。
- prepare 阶段的 `rigid_objectivity` 归一化一并修正：力矩尺度改为 `forceScale × 杆长`，
  阈值 `1e-10` 不变，避免近零 body torque 分量把浮点舍入判成物理失败。
- `tool/hair/rodBehaviorPrototype.cpp`、`hairClumpControl/LongRun` 是**冻结原型**，
  继续按旧标签输出，不作为验收入口，也不改写它们的历史结论。
- 源码一改，新 run 的源身份就变了：旧的 6 PASS / 18 FAIL、24 项中 15 项 FAIL
  都保留原记录（见 [hair-landing 记录](../../rationale/hair-landing-20261119.md)），
  本政策不追溯重判。
