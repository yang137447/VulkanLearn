天气、环境光与 GI 长期路线

这份路线把 procedural sky、SSAO/GTAO、SSR、reflection probe、VLM、全局体素、DDGI 与 Lumen-like hybrid GI 放到同一张图里。 它不是下一周就要全部实现的任务清单，而是用来判断每个系统该解决什么问题、依赖哪些数据、应该在什么时候进入 VulkanLearn。

procedural sky SSAO / GTAO SSR reflection probe VLM / irradiance probe global voxel Lumen-like GI weather system

当前定位：先完成 GPU-first procedural sky IBL。它是后续 reflection probe、VLM、DDGI、Lumen-like 系统的天空光源与 fallback，不要一开始就把问题拉到完整动态 GI。

系统地图

Diffuse / 漫反射

Sky SH、VLM、irradiance probe、DDGI、Lumen diffuse GI。重点是低频间接光、空间位置、遮挡和光照传播。

Specular / 镜面反射

Sky prefiltered cubemap、SSR、reflection probe、planar reflection、RT reflection、Lumen reflections。重点是方向、roughness、fallback。

Occlusion / 遮挡

SSAO、GTAO、bent normal、contact AO、distance field AO、voxel occlusion。重点是让环境光不要从不该来的方向进来。

Screen-space

SSAO/GTAO、SSR、SSGI、contact shadow。依赖当前帧 depth、normal、scene color，成本低但只能看到屏幕内信息。

World-space

Reflection probe、VLM、DDGI、global voxel、surface cache。能覆盖屏幕外信息，但需要额外场景表示和更新策略。

Temporal / 历史帧

SSR denoise、SSGI、probe update、radiance cache、cloud/fog accumulation。需要 motion vector、history buffer 和稳定重投影。

关键数据依赖

全局天空与天气源

  • SkyParametersGPU、WeatherStateGPU、time-of-day、sun/moon direction
  • 生成 global sky SH、global sky cubemap、global prefiltered cubemap
  • 作为 reflection probe、VLM、DDGI、Lumen-like 的天空 fallback

屏幕空间数据

  • depth、normal、roughness、metallic、scene color、motion vector、history color
  • 服务 SSAO/GTAO、SSR、SSGI、contact AO、TAA/temporal denoise
  • 这一步会推动 forward+extra buffers 或 deferred/GBuffer 的架构选择

局部探针数据

  • reflection probe: local cubemap + prefilter + box projection + blending
  • VLM / irradiance probe: world position -> interpolated SH irradiance
  • 都需要与 global sky fallback 合成

全局场景表示

  • global voxel、SDF、surface cache、mesh card、radiance cache
  • 服务动态 GI、屏幕外反射、遮挡和体积效果
  • 这是 Lumen-like 系统真正开始的地方
Specular fallback:
SSR hit -> local reflection probe -> global sky prefiltered cubemap

Diffuse fallback:
local irradiance / VLM / DDGI -> global sky SH

Occlusion:
GTAO / bent normal / voxel visibility modulates diffuse environment

长期大阶段

1

GPU-first Sky Foundation

先完成当前正在规划的天空地基：GPU 参数、屏幕天空、SH diffuse IBL、cubemap/prefilter specular IBL、dirty 与分帧更新。

前置知识
  • fullscreen sky
  • SH9 / split-sum IBL
  • compute buffer / image barrier
目标
  • 天空和 IBL 同源
  • CPU 只做控制面
  • GPU 生成环境资源
执行
  • SkyParametersGPU
  • EnvironmentSHGPU
  • procedural cubemap / prefilter
验收
  • 天空、diffuse IBL、specular IBL 趋势一致
  • 无 GPU -> CPU readback stall
2

Geometry Buffers / 屏幕空间基础

补齐 SSAO、SSR、SSGI、Lumen screen trace 都会用到的屏幕空间输入。

前置知识
  • view/world position reconstruction
  • normal encoding
  • motion vector / history
目标
  • 决定 forward+extra buffers 或 GBuffer
  • 稳定输出 depth/normal/material data
执行
  • 新增 normal/roughness/metallic buffer
  • 建立屏幕空间重建函数
  • 规划 history resources
验收
  • debug view 能检查 depth/normal/roughness
  • 移动相机时重建稳定
3

SSAO / GTAO

先做环境遮挡，让天空 SH 和后续 GI 不再无脑照亮所有缝隙。

前置知识
  • hemisphere sampling
  • depth/normal reconstruction
  • bilateral blur
目标
  • 局部接触遮挡
  • 环境光可被 AO 调制
执行
  • 先 SSAO，再升级 GTAO
  • AO 输出参与 indirect diffuse
  • 保留 debug view
验收
  • 墙角、接触面变暗
  • 无明显 halo / flicker
4

SSR / 屏幕空间反射

用当前屏幕中的 scene color 和 depth 补充镜面反射，解决 sky cubemap 过于空旷的问题。

前置知识
  • ray marching
  • depth intersection
  • roughness fade / temporal denoise
目标
  • 屏幕内物体能出现在反射里
  • 未命中回退到 probe/sky
执行
  • SSR trace pass
  • resolve / denoise pass
  • 混合 sky/probe fallback
验收
  • 低 roughness 表面能反射屏幕内物体
  • 屏幕边缘未命中渐隐自然
5

Reflection Probe / 局部镜面反射

补齐 SSR 的屏幕外缺口，让室内、房间、局部区域拥有自己的 specular IBL。

前置知识
  • cubemap capture
  • box projection
  • probe blending
目标
  • 局部 reflection override
  • sky cubemap 作为 fallback
执行
  • probe capture 6 faces
  • probe prefilter
  • runtime probe selection
验收
  • 室内金属反射房间而不是只反射天空
  • probe 边界过渡稳定
6

VLM / Irradiance Probe

给动态物体提供局部漫反射间接光，解决室内外漫反射环境光不匹配。

前置知识
  • SH irradiance
  • trilinear interpolation
  • probe visibility / leaking
目标
  • position -> local diffuse irradiance
  • global sky SH 作为 fallback
执行
  • probe grid / sparse samples
  • local SH storage
  • dynamic object sampling
验收
  • 角色进入室内后暗部跟随局部光照变化
  • 没有严重漏光
7

Weather / Fog / Cloud / Precipitation

把 sky、fog、cloud、wet material、wind、precipitation 合成一个可过渡的天气状态系统。

前置知识
  • height fog / aerial perspective
  • cloud layer / volumetric cloud
  • material wetness
目标
  • clear / cloudy / foggy / rainy / storm
  • 统一天气参数驱动渲染
执行
  • WeatherStateGPU
  • fog/cloud/precipitation passes
  • wet material parameters
验收
  • 晴天到暴雨可平滑过渡
  • 天空、云、雾、地表反馈一致
8

DDGI / Global Voxel / Radiance Cache

进入真正的动态 GI 表示层，用 probe grid、voxel 或 radiance cache 表示屏幕外间接光。

前置知识
  • scene representation
  • radiance injection
  • temporal filtering
目标
  • 粗略动态 GI
  • 屏幕外间接光信息
执行
  • DDGI probe grid 或 voxel volume
  • sky/direct light injection
  • visibility / relocation
验收
  • 大范围间接光随光源/天空变化
  • 帧间稳定且可控
9

Lumen-like Hybrid GI / Reflections

最后再考虑类似 Lumen 的混合系统：screen trace、world trace、surface cache、radiance cache、temporal resolve 共同工作。

前置知识
  • 前面所有阶段
  • surface cache / SDF / cards
  • hybrid tracing
目标
  • 动态 diffuse GI
  • 动态 reflections
  • 统一 fallback 层级
执行
  • screen traces
  • world-space traces
  • surface/radiance cache
验收
  • 动态场景 GI/反射有合理屏幕外信息
  • 质量/性能档位可切换

推荐顺序

1. GPU-first procedural sky IBL: 先建立全局 fallback
2. Geometry buffers: 补齐 depth / normal / roughness / motion vector
3. SSAO/GTAO: 先让环境光有局部遮挡
4. SSR: 用屏幕内信息补 specular 反射
5. Reflection probe: 用世界空间 probe 补 SSR 屏幕外缺口
6. VLM / irradiance probe: 给动态物体局部 diffuse indirect
7. Weather/fog/cloud: 把天空、雾、云、降水、湿润统一成状态系统
8. DDGI / voxel / radiance cache: 再进入动态 GI
9. Lumen-like hybrid: 最后做混合 GI/reflection 架构

Lumen-like 的边界

它不是单个 pass

Lumen-like 系统更像一个组合架构：screen trace、world-space scene representation、surface cache、radiance cache、temporal accumulation 和 fallback 层级一起工作。

现在不要直接跳到这里

如果没有稳定的 screen-space buffers、SSR fallback、probe fallback、历史帧和 debug view，直接做 Lumen-like 会很难定位问题。

Diffuse 路线

Sky SH -> VLM / irradiance probe -> DDGI / radiance cache -> Lumen-like diffuse GI。

Specular 路线

Sky prefiltered cube -> SSR -> reflection probe -> world trace / Lumen-like reflections。

遮挡路线

SSAO/GTAO -> bent normal -> probe visibility -> voxel/distance-field occlusion。

完整天气系统的汇合点

天气状态驱动

  • WeatherPreset：晴天、多云、阴天、雾、雨、暴风雨
  • WeatherStateGPU：风、湿度、云量、降水、能见度、湿润强度
  • 状态曲线驱动 sky、cloud、fog、IBL、wet material

渲染系统响应

  • sky / atmosphere：颜色、太阳、月亮、曝光
  • cloud / fog：遮挡、散射、能见度
  • GI / probes：低频或分帧更新
  • surface：roughness、wetness、puddle、ripple

最终目标：配置一条晴天 -> 多云 -> 阴天 -> 小雨 -> 暴雨 -> 雨后放晴的循环，天空、云、雾、光照、IBL、反射、地表湿润和降水都能以可调预算稳定变化。

学习资料

Sky / IBL 基础 继续使用 Sky Pass 与程序化天空学习路线 作为当前阶段主线。
Vulkan 同步与资源状态 读 Vulkan Synchronization and Cache Control。 重点是 compute write -> fragment read、image layout、buffer barrier、frames in flight。
SSAO / GTAO 先理解 SSAO 的 depth/normal 重建，再读 Practical Realtime Strategies for Accurate Indirect Occlusion 这类更高质量 AO 资料。
SSR 读 AMD FidelityFX Stochastic Screen Space Reflections。 第一轮重点看输入数据、ray marching、roughness、fallback 和 denoise。
Reflection Probe / IBL 对照 Real Shading in Unreal Engine 4 的 split-sum IBL，以及本项目现有 prefilter 生成链路。
DDGI / Probe GI 读 NVIDIA RTXGI / DDGI，先理解 probe grid、visibility、relocation 和 temporal update。
Lumen 读 Unreal Engine Lumen Global Illumination and Reflections 和 Lumen Technical Details。 只把它作为长期架构参考，不作为当前实现目标。
