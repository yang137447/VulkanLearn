Sky Pass 与程序化天空学习路线

当前工程已经具备独立 Sky Pass、HDRI cubemap、SH 漫反射 IBL、prefiltered specular IBL 与 BRDF LUT。 下一步不是从零搭天空，而是把现有 HDRI 天空演进成可参数化的 procedural sky，再逐步接入动态环境光与分帧更新。

fullscreen triangle view ray reconstruction procedural sky SH9 diffuse IBL prefiltered cubemap frame-sliced updates

当前学习重心：先让程序化天空只影响屏幕背景，保留现有 HDRI IBL 作为基准。等视觉和参数链路稳定后，再让程序化天空同步到 SH、cubemap 和 prefilter。

教程完成后的预期效果

这条路线的终点不是立刻做出生产级 Sky Atmosphere，而是得到一个可调、可解释、能接入 PBR/IBL、 后续能扩展到大气、云和 time-of-day 的 procedural sky 原型。

最终应该看到

  • 天空背景由 sky.frag 根据世界空间视线方向实时生成
  • 天顶色、地平线色、下半球颜色、太阳盘、太阳 glow 与太阳强度都可调
  • 天空太阳、主 directionalLight、直接光和阴影方向能对齐
  • 修改天空参数后，非金属材质暗部会跟着天空颜色变化
  • 金属和低 roughness 材质能反射出程序化天空的大趋势

阶段效果对齐

  • 阶段 1：只影响屏幕背景，PBR IBL 仍来自 HDRI
  • 阶段 2-3：天空参数数据化，太阳方向与 directional light 对齐
  • 阶段 4：compute shader 生成 procedural sky -> SH diffuse IBL
  • 阶段 5：procedural sky -> cubemap -> prefilter -> specular IBL 跑通
  • 阶段 6：通过 dirty flag 和分帧更新逐步收敛动态环境资源

一句话目标：教程完成后，应拥有一个从屏幕背景到 diffuse IBL、specular IBL、动态更新都能打通的 procedural sky 原型；第一版不追求物理极致，但要保证链路完整、方向正确、后续能自然升级。

长期大阶段：直到完整天气系统

当前教程主要覆盖大阶段 1，并为大阶段 2 的动态更新打基础。后续天气系统应沿着同一套 sky、IBL、dirty 和分帧更新链路继续扩展。

1. Sky Foundation

  • 完成 procedural sky 背景、太阳方向、SH diffuse IBL、cubemap/prefilter specular IBL 闭环
  • CPU 只负责 SkyParameters、light 同步、dirty 标记、更新预算和 dispatch 调度
  • CPU 不采样 procedural sky，不积分 SH，不生成 cubemap 或 prefilter
  • procedural sky -> SH / cubemap / prefilter 逐步落到 compute shader 或 GPU pass

2. Dynamic Sky / Time-of-Day

  • 太阳/月亮方向、时间曲线、曝光补偿
  • 屏幕天空每帧变化，SH、cubemap、prefilter 低频或分帧收敛
  • 为日出、正午、黄昏、夜晚建立可调参数曲线

3. Physical Atmosphere

学习 Rayleigh、Mie、transmittance LUT、sky-view LUT 和 aerial perspective，让天空颜色和低角度太阳更自然。

4. Fog / Aerial Perspective

接入 height fog、distance fog、directional inscattering 和 scene depth 合成，让天气开始影响场景空间。

5. Cloud System

先做 2D cloud layer，再升级 volumetric cloud；接入云量、风向、密度、高度、云阴影和太阳遮挡。

6. Weather State System

定义 WeatherPreset、WeatherState、状态过渡、风速、湿度、云量、降水强度和能见度。

7. Precipitation / Surface

接入雨、雪、湿润材质、roughness 变化、puddle/wetness mask、涟漪和可选镜头雨滴。

8. Full Weather System

统一天气配置、runtime controller、time-of-day、debug view、性能档位和热更新调参入口。

直接 GPU 接入的数据流

从第一版 procedural sky 开始，天空参数和派生环境数据就直接走 GPU 资源，不先绕一条 CPU 计算链路。

scene/config/defaults -> CPU 只做参数准备与调度
SkyParametersGPU buffer in GlobalSet
sky.frag 读取 SkyParametersGPU 生成屏幕背景
proceduralSkyToSH.comp 读取 SkyParametersGPU 并写入 EnvironmentSHGPU
pbr.frag 读取 EnvironmentSHGPU 计算 diffuse IBL
proceduralSkyToCubemap.comp 生成 environmentCube / prefilteredEnvironmentCube
pbr.frag 读取 specular IBL

CPU 只做控制面

  • 解析 JSON 或默认参数
  • 根据 directional light 计算太阳方向
  • 上传 SkyParametersGPU
  • 设置 dirty 标记、更新预算和 dispatch 调度

明确不要做

  • 不把 GPU 算出的 SH readback 到 CPU 再填 UBOGlobal.environmentSH
  • 不在 CPU 侧复制 procedural sky evaluator 去积分 SH
  • 不把长期 sky 参数继续塞进已经拥挤的 UBOGlobal

当前基线

已经具备

  • 启动阶段生成 BRDF LUT
  • 场景加载阶段把经纬 HDR 转成 environmentCube
  • 基于 environmentCube 生成 prefilteredEnvironmentCube
  • 基于 HDRI 生成 environmentSH[9]
  • sky pass 在 geometry 后绘制背景
  • 全局 UBO 已包含 invView 与 invProjection

下一步缺口

  • 程序化天空参数结构与配置入口
  • sky.frag 从 cubemap 采样切换到程序化颜色
  • 太阳方向与 directional light 的明确绑定
  • 程序化天空到 SH 的低频同步
  • 程序化天空到 cubemap / prefilter 的动态更新策略
  • dirty 标记、更新预算与分帧调度

架构原则

Sky 是 pass

使用独立 Sky Pass 和 fullscreen triangle，不引入天空盒 mesh。后续大气、云和 aerial perspective 都从同一个 pass 演进。

环境是场景资源

天空与环境资源属于 GlobalSet，不是某个 pass 的局部输入。HDRI、procedural sky 和 IBL 派生资源都应保持场景级语义。

先背景，后 IBL

第一版 procedural sky 只替换屏幕背景。SH、cubemap、prefilter 和分帧更新在后续阶段接入，避免学习跨度过大。

GPU-first 派生

阶段 1 的天空派生资源不走 CPU 计算。CPU 只上传参数、设置 dirty 标记和调度任务，SH、cubemap、prefilter 由 GPU 生成。

渲染流程

1. shadow

渲染阴影资源，供 geometry 直接光阴影使用。

2. geometry

写入 HDR color 与 scene depth，输出可被 sky 加载。

3. sky

使用 load/store 加载颜色和深度，只补背景像素。

4. post chain

后处理、bloom、tone mapping 消费最终 HDR 场景颜色。

sky 继续在 geometry 后执行。程序化天空第一版不改变 pass 顺序，只替换 sky shader 的颜色来源。

SkyParameters 与 GPU 配置入口

提供最小参数集合，并从第一版开始接入独立 SkyParametersGPU buffer，供 sky shader 和 compute shader 直接读取。

目标
  • 提供最小 sky 参数集合
  • 建立直接供 shader 和 compute 读取的 SkyParametersGPU buffer
  • 优先使用 vec4 字段，降低 std140 / std430 对齐学习成本
  • 避免一开始实现完整物理大气
  • 让旧场景有稳定默认值
需要学习的资料
  • source/baseStructs.h：参考现有 GPU 数据结构风格，不把 sky 参数继续塞进 UBOGlobal
  • source/renderSystem.cpp：参考 per-frame buffer 更新与 descriptor 使用路径
  • source/sceneLoader.cpp：scene/config JSON 读取方式
  • Vulkan Shader Resource Layout：std140 对齐规则
  • descriptor set layout、descriptor update、frames-in-flight buffer 管理
大致修改步骤
  • 新增 SkyParametersGPU，并为它创建独立 GPU buffer
  • 在 GlobalSet 中新增 sky 参数 buffer binding
  • 新增 skyParameters.glsl 或等价 include，集中声明 GPU 侧布局
  • CPU 只负责默认值、JSON 覆盖、light 同步和 buffer upload
  • 把 sky.frag 中硬编码常量替换为 GPU buffer 读取
  • 明确参数放 scene environment 还是 config；第一版优先最少改动路径
验收结果
  • 改 JSON 或默认值即可改变天空
  • 没有把 procedural sky 参数追加进 UBOGlobal
  • RenderDoc 中能看到 SkyParametersGPU 作为独立 GlobalSet buffer 被绑定
  • sky.frag 直接读取 GPU buffer
  • 缺省参数场景能正常运行
  • RenderDoc 或 shader 反射中能看到 sky 参数绑定符合预期

Procedural Sky 到 SH 漫反射环境光

用 compute shader 在 GPU 侧按程序化天空采样球面并投影到 9 项 radiance SH，沿用现有 EvaluateIrradianceSH() 消费路径。

目标
  • 让程序化天空不只是背景，也能影响低频漫反射环境光
  • 使用 compute shader 生成 9 项 radiance SH
  • 沿用现有 diffuse irradiance 计算语义
  • 只在参数变化时更新 SH
  • 避免 GPU -> CPU readback 成为常规路径
需要学习的资料
  • Stupid Spherical Harmonics Tricks：SH 基底、投影、重建
  • Filament PBR：diffuse IBL、irradiance、exposure
  • source/pipeline/environmentSHGenerator.cpp 只作为 SH 数学参考
  • shader/glsl/common/lighting.glsl 与 shader/glsl/pbr.frag
  • compute reduction、storage buffer barrier、跨帧读写同步
大致修改步骤
  • 新增 proceduralSkyToSH.comp，GPU 侧采样 procedural sky 并投影到 SH
  • CPU 只上传 SkyParametersGPU，设置 dirty 标记并调度 dispatch
  • 第一版可用 partial SH pass 加 final reduce pass
  • SH 结果写入 EnvironmentSHGPU storage/uniform buffer，PBR 直接读取
  • procedural sky 路径不经过 UBOGlobal.environmentSH
  • 在 lighting.glsl 中把 SH 来源抽象为 GPU buffer 读取
验收结果
  • 非金属材质环境漫反射随天空颜色变化
  • 金属表面的 diffuse IBL 仍按 metallic 被压低
  • environmentIntensity 仍统一控制强度
  • 可回退到 HDRI SH 或默认 SH，且 SH 不在每帧无条件重算
  • procedural SH 生成过程中没有 GPU -> CPU readback stall
  • compute 写入和 PBR 读取之间有明确 barrier 或帧延迟策略

分帧更新与动态环境状态

把昂贵环境更新拆成低频任务，支持 cubemap face、prefilter mip 和 SH 的 dirty 状态与更新进度。

目标
  • 把昂贵环境更新拆成低频任务
  • 支持 face/mip/SH 的独立进度
  • 避免 time-of-day 每帧全量重建 IBL
  • 让背景、SH、specular IBL 最终收敛到同一套 sky 参数
需要学习的资料
  • Vulkan Tutorial: Frames in Flight
  • Vulkan Synchronization and Cache Control
  • source/renderSystem.cpp：command buffer、submit、present 流程
  • environmentCubemapGenerator.cpp 与 environmentPrefilterGenerator.cpp
大致修改步骤
  • 为 sky、SH、cubemap、prefilter 设置 dirty 和 cursor
  • 每帧只消费有限更新预算，例如一个 cubemap face 或一个 prefilter mip
  • 必要时使用双缓冲或延迟替换
  • 增加调试输出或 UI 状态，能看到当前更新到哪个 face/mip
  • 先让全量更新稳定，再逐步切成分帧更新
验收结果
  • 连续变化时帧时间不因全量 IBL 更新大幅抖动
  • 更新进度可观察
  • 旧环境资源在新资源未完成前仍可稳定用于渲染
  • 无 validation layer 的 layout/access/lifetime 错误
  • 分帧更新完成后，背景、SH、specular IBL 最终一致

学习资料路线

阶段 A：Sky Pass 与 Render Graph 复盘 读 Vulkan Render Pass 和 Vulkan Synchronization and Cache Control。 只抓 attachment、load/store、layout transition、stage 和 access mask。
阶段 B：屏幕空间天空与视线重建 先复盘本项目 sky.vert、sky.frag、commonUbo.glsl 和 UBOGlobal。 这一段以源码为主，暂缓外部资料。
阶段 C：第一版 Procedural Sky 看 Preetham daylight model 和 Hošek-Wilkie Sky Dome Appearance Project。 第一轮只理解太阳高度、turbidity、天空颜色关系，不直接实现完整模型。
阶段 D：SH 漫反射环境光 读 Stupid Spherical Harmonics Tricks 和 Filament: Physically Based Rendering。 重点是 SH 基底、投影、重建、diffuse irradiance、compute reduction 和 storage buffer 同步。
阶段 E：镜面 IBL 与 Split-Sum 读 Real Shading in Unreal Engine 4 和 Physically-Based Shading at Disney。 对照 prefilterEnvMap.comp、brfdLut.comp 和 lighting.glsl。
阶段 F：分帧更新与动态环境 复读 Frames in Flight 和 Vulkan 同步章节。关注多帧资源所有权、fence 等待点、image barrier 和 shader read/write。
阶段 G：生产级大气与长期方向 做完第一版 procedural sky 后再看 Hillaire Sky and Atmosphere、 UnrealEngineSkyAtmosphere、 Bruneton atmospheric scattering 和 Unreal Sky Atmosphere Component。

验证清单

Cubemap 朝向

  • 地平线保持水平
  • 上下没有翻转
  • 左右没有镜像
  • 相机 yaw 和 pitch 与环境方向映射正确

Render Graph 行为

  • geometry 正确写入 HDR 颜色和深度
  • sky 正确加载前序输出
  • sky 只在背景像素通过深度测试

视觉检查

  • 天空在所有几何体背后可见
  • bloom 与 tone mapping 不会吞掉天空背景
  • 场景未覆盖全屏时不会出现黑底

Procedural Sky 检查

  • 天顶、地平线、下半球颜色保持世界空间稳定
  • 太阳盘位置与 directional light 方向一致
  • 太阳强度进入 HDR 链路后不过度失控
  • 明确记录 PBR IBL 是否仍来自 HDRI

第一版非目标

第一版程序化天空只替换屏幕背景颜色，不解决下面这些内容：

  • 解析式大气
  • 云层渲染
  • procedural sky 到 SH 漫反射 IBL 的同步
  • procedural sky 到 prefilter 镜面 IBL 的同步
  • 昼夜切换与 time-of-day 曲线
  • 天气系统
  • 分帧环境更新
