# MotionBricks 官方演示对齐计划

用户于 2026-11-20 确认。目标是对齐公开运行时的运动行为与官方演示观感，
不将“能移动”或单张截图等同于动作质量一致，也不预设需要重新训练。

## 展示对象

- SOMA 原生骨架作为模型输出准确性基准。
- UE5 Manny Simple 作为最终游戏角色的演示与重定向验收对象。
- 当前 UEFN Mannequin 保留为回归对照。
- Manny 来自本机安装的 UE5 模板，导入专属资源工作树，使用独立 skeleton、
  retarget profile 和参考姿态校准。展示材质不宣称复现完整 UE 材质。

## 分阶段实施

| 阶段 | 工作 | 验收 |
| --- | --- | --- |
| 1 | 固定官方代码、ONNX、Smart Primitive 与 BVH 版本；整理公开 Python 与 UE 演示的已知差异 | 每个动作有输入与参考，未公开细节明确列出 |
| 2 | SOMA 原生骨架与 context/target/轨迹/接触调试显示，保存输入输出并回放 | 同一数据可重复比较，区分生成与重定向 |
| 3 | 对齐官方目标采样、混合、根轨迹速度缩放、整体放置和 token 参数 | 输入张量逐项容差比较 |
| 4 | 对齐期望速度、当前朝向、加减速、再生成条件、Idle 循环与生成过渡、异步衔接 | SOMA 原生走跑停、90/180 度转向与连续输入无明显跳变 |
| 5 | 同一 SOMA 输出驱动原生骨架和 Manny，检查骨盆、肩臂、腿脚、比例与根运动分离 | 保留动作节奏与重心变化，无明显骨骼扭转交叉 |
| 6 | 按官方实际使用范围核对接触处理，处理碰撞反馈历史并测量执行后端时延 | 接触误差、脚滑、碰撞响应和暂停倍率均有数据 |
| 7 | 官方、引擎 SOMA、Manny 的相同输入对照录屏；多帧率与长时回归 | 视频、指标、测试和剩余差异清单完整 |

阶段 4 后先验收 SOMA 原生动作，阶段 5 后再验收游戏角色。
Manny 资产接入可提前完成，不能替代阶段 2–4 的官方流程对齐。
现有双角色场景使用独立推理实例，不等同于阶段 5 的同一源输出对照。

## 工程边界

代码在 `codex/motionbricks`，资源在 `codex/motionbricks-assets`。
保留现有 UEFN 演示，不覆盖主资源仓库或源 UE 工程。
模型训练仅在排除目标输入、控制、重定向与接触处理差异后仍有明确能力缺口时评估。
